# Study Coach · 学习教练

ai-study-kit 的工具链很全（答题站 / 课程 / 闪卡 / 错题精讲 / 播客 / 部署），但**没人该为了学习去记命令**。本指令就是教练：先看状态，再给建议，最后带你执行。

每次执行固定三步，不要跳步：

## Step 1 · 探测状态（永远先做；全程只读，≤1 分钟）

按 [`references/state.md`](references/state.md) 的探测协议采集七个字段，拼成「学习状态快照」：

| 字段 | 回答的问题 |
|------|-----------|
| **仓库** | 当前目录是 ai-study-kit 仓库吗？还是根本没 clone？ |
| **主题** | 激活主题是哪个（`EXAMPLE_THEME`，默认 `dev-intro`）？是演示还是用户自己的主题？ |
| **库存** | 题库 N 题 · 闪卡 N 张 · 课程 N 节 · 错题串讲 N 簇 |
| **进度** | 已答 N/M · 未毕业错题 N · 到期闪卡 N · 课程已读 N/M（coursesRead 口径，见 state.md） |
| **AI** | `.env` 的 LLM 三项配齐了吗（**绝不打印 key 的值**，只报 配齐/缺失） |
| **服务** | `:8787` 后端在线吗（grill 拉错题、看课程需要它） |
| **意图** | 用户这句话里有没有明确想干的事（见下方意图路由表） |

仓库不存在时跳过其余探测，直接进 F1（bootstrap）。

## Step 2 · 汇报快照 + 推荐 + 菜单

用这个固定模板输出（数字全部来自 Step 1 实测，不许编）：

```
📊 学习状态快照
- 仓库: <路径> · 主题: <theme>（demo / 用户主题）
- 库存: 题 N · 闪卡 N · 课程 N 节 · 错题串讲 N 簇
- 进度: 已答 N/M · 未毕业错题 N · 到期闪卡 N · 课程已读 N/M
- AI: <配齐 ✅ / 缺 LLM 配置 ❌> · 服务(:8787): <在线 ✅ / 离线>

👉 推荐现在做：<一个动作 + 一句为什么>
回复编号选择，或直接说你想干的事：
  1️⃣ 每日学习   2️⃣ 错题串讲   3️⃣ 做播客     4️⃣ 开新主题
  5️⃣ 产课/加课  6️⃣ 改内容     7️⃣ 校验发布   8️⃣ 部署
  9️⃣ 诊断问题   0️⃣ 重新扫描
```

### 推荐算法（用户没有明确意图时，按顺序取第一个命中的）

1. 仓库不存在 → **F1 初始化项目**
2. 激活主题是 `dev-intro`（演示内容），且用户有自己想学的东西 → **F2 开新主题**（demo 的 git/Linux 题不是学习材料）
3. 到期闪卡 > 0 → **F3 每日学习**（先复习——记忆在衰退，新知识可以等）
4. 未毕业错题 ≥ 3 → **F4 错题串讲**（错题攒够了，值得 LLM 聚类深挖一轮）
5. 有未答题 且 课程未读满（lessonsRead < 总数）→ **F3 每日学习**（先建概念再做题——按当日课表读对应课，答题站课程页打开即自动记已读）
6. 有未答题 且 课程已读满（lessonsRead = 总数）→ **F3 每日学习**（直接刷题）
7. 题全答完 且 正确率 ≥ 80% → **F5 做播客**（转被动巩固）或 **F2 开新主题**
8. 题全答完 且 正确率 < 80% → **F4 错题串讲**，仍不达标则 **F6 补课**（课程讲解质量不够）

### 意图路由表（用户话里带了这些词，直接跳对应流程，仍要先跑 Step 1 验前置）

| 用户说 | 流程 | 硬前置（缺了先补） |
|--------|------|-------------------|
| 网页 / 答题站 / 跑起来 / demo | F1 | — |
| 我要学 X / 换主题 / 新主题 | F2 | — |
| 学什么 / 复习 / 今天刷什么 | F3 | 应用能跑（`pnpm dev`） |
| 错题 / 串讲 / 精讲 / 为什么错 | F4 | 后端在线 + 有错题 + AI 配齐 |
| 播客 / 音频 / 通勤听 | F5 | AI 配齐；TTS 没配可 `--no-tts` 只出逐字稿 |
| 产课 / 加课 / 讲义 / 教我 X | F6 | `course-spec.json` + AI 配齐 |
| 改题 / 改课 / 改卡 / 改日程 | F7 | — |
| 校验 / 检查 / 能不能发布 | F8 | — |
| 部署 / 上线 / 服务器 / pm2 | F9 | 本地 build 通过（先走 F8） |
| 不同步 / 进度丢了 / 页面坏了 | 诊断 | — |

## Step 3 · 执行选定流程

读 [`references/flows.md`](references/flows.md) 中对应 playbook，逐步执行：

- 每个流程末尾都有**完成标志**，达到才算完；达不到要如实说卡在哪。
- playbook 里的选择点（主题名、播客风格、改哪节课）才问用户；其余步骤直接做。
- 流程之间有接力：F2 完成接 F3 开始学；F4 读完串讲接「重做错题集」；F8 全绿才算可发布，接 F9。

## 硬红线（执行任何流程前自查；完整版见仓库 `AGENTS.md`）

1. `apps/quiz-app/src/data/*.json` 和 `public/study/` 是**同步产物，禁止手编**——内容只改 `examples/<theme>/` 下的源文件。
2. `apps/quiz-app/progress.json` 是**运行期数据**：禁止提交、禁止手编；需要清进度用 app 内的「重置」入口，绝不手改文件。
3. 切换主题只改 `EXAMPLE_THEME` 环境变量一处——课程入口 `Courses.tsx` 读 sync 产物 `theme.json` 自动跟随（首页分组可选改 `apps/quiz-app/src/lib/topicOrder.ts`）。
4. 改任何发布内容（课程/题/闪卡/文档）后必跑 `pnpm run scan`，命中数必须为 0——发布物里不许出现真实企业品牌名。
5. 多选题判分是**全对才算对**；改题尽量保留旧题 id（进度按 id 存，换 id 会丢进度）。
