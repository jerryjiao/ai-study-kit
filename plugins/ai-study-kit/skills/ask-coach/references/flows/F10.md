# F10 · 陪练教学（coach）

> 属 [Flow Playbooks](../flows.md)——「流程 → 文件」目录、公共约定与其余流程都在那；本文件只装 F10 一个 playbook。

**目的**：对话式把考点一个个**教懂 → 当场考过 → 逐考点落盘**，跨天可续。学习的主线在 F10——[F3](../flows.md) 刷题与 [F4](F4.md) 错题串讲是汇入：教过的去 F3 刷题验证；刷错的题若根因是概念缺口，回流 F10 开补站。区别于 [F6](F6.md)（产持久课程 html 的内容工厂）。低能量时段有不开站的轻形态——**微块模式**（单考点口述 3 题，5-15 分钟，见下方专节）；**任何会话收尾固定留下站预告**（开环钩子，见「收尾开环预告」节）。

**教学法事实源**：本 flow 只编排「什么时候做什么」；「怎么做才算对」以 [`references/coach.md`](../coach.md) 为准——三段式纪律（§3）、符号型「要死记」标注（§4）、锚点金句标准（§5）、考法五模式与过关判定（§6）、定义零容忍（§7）、诊断纠偏表（§9）。执行本 flow 前先读 coach.md；条文不整段贴进对话，对话里只出现条文的执行结果。

### 什么时候用

- 用户说「继续学习 / 接着学 / 陪我练 / 学透 X / 学一下 X / 讲讲 X」。
- 用户说「就学 5 分钟 / 今天很累 / 轻轻学一下 / 没状态」（低能量轻启动）→ **微块模式**（见下方「微块模式」节，不开站）。
- 推荐算法命中**续站**（存在进行中的站）——报站名 + 待办数，**用户点头才开跑**：续站是建议不是指令，自动开跑是打扰。
- F4 串讲发现错因的根子是**概念没懂**（不是粗心、不是题式陷阱）→ 回 F10 开补站，把缺口当新站教。

### 什么时候不用

- 检验掌握程度 → F3 刷题；弄懂做错的题 → F4 复盘。两者都不教新知识——**教新知识只有 F10 一条路**，这条边界让教学不散落进刷题对话。
- 用户输入是求助不是求学（「学了没用 / 记不住 / 想放弃 / 我卡住了」）→ 先走诊断纠偏入口，诊断完再进教学循环。
- 教材本身要改 → [F6/F7](../flows.md) 工厂链。

### 微块模式 · 轻启动（5-15 分钟；v0.26，#123）

**是什么**：**不开站**的陪练微形态——单考点口述 3 题（或单考点热身一题），5-15 分钟收尾。「累的晚上也学得动」是一等路径：学习者不必走整站流程，微块完成即计入该考点口述进度与**当日触达**（首页「今天已触达」徽标亮、断档清零——口述走 #122 实时回流，网站刷新即见）。

**什么时候进微块**：

- 学习者原话带「就学 5 分钟 / 今天很累 / 轻轻学一下 / 没状态 / 随便学点」——低能量场景**直接进微块**，不劝「再坚持一下开个站」。轻启动的门越低，学习越连续。
- 有进行中站但学习者明显只想轻量（「今天没力气续站」）→ 微块不动站状态，次日续站照旧——两者并列不互斥。

**四步流程**：

1. **选考点报一句**：优先**下一站考点**（与全景推荐卡同判据——落后日程 > 补弱 > 结构序），一句话报块：「今天轻量：EP-03 chmod，口述 3 题，几分钟完事」。不问「想学什么」——排班是教练的活（同第 0 步纪律）。学习者更想动手做题时给**热身一题**（下一站考点挑一题，`?ep=` 考点直达答题站——与断档回归卡同一套挑题，答完即计入该考点答题进度）。
2. **口述 N 题**（默认 3，学习者可改 2-5）：从考点概念口头出题，学习者口答，教练按 [coach.md](../coach.md) §6.6 的判分精神判定（关键属性不丢不错，机制或用法至少讲对一侧）。**不教新**：微块是「练」不是「教新」——考点完全没基础时如实说，换下一个有基础的考点（或一句话给锚点金句再问，不展开讲）。
3. **每答一题即落盘回流**：`oral-attempts.json` 追加一条 + POST `/api/oral-attempts` 实时回流——单源 [`contracts.md`](../../../../references/contracts.md) 契约二，`source: "recall"`、`target` 带 EP 前缀、`at` 真实 `Date.now()`。**这是微块计入进度的唯一证据通道**：三题答完，全景/首页刷新即见（当日触达亮、口头计数+3）。
4. **钩子收尾 + 落预告**：先一句「今天到这就行」确认「学了」这个事实，再给固定形状的**下站预告**——「下次：EP-XX <考点名> 口述 3 题，约 5 分钟」（三件齐：考点 + 动作 + 时长量级；考点收尾前跑 `plan-report --json` 读 `next` 字段现算，不自估——见下方「收尾开环预告」节）。预告写 `study/records/next-hook.json`（契约二「下站预告」）。**禁债务/欠账文案**：不出「落后 / 欠 N 站 / 要补回来 / 进度拉下」类字样（低压力场景的语气红线：微块的价值就是「学了」这个事实本身，收尾只确认它、给一个可选的下一步钩子，绝不制造亏欠感）。学习者想继续就自然续（可转正式开站），不推。

**与站的关系**：微块**不开站、不建** `study/records/` **记录、不动 COACH.md、不动 plan.json 单元**（契约三零触发）。微块答错不进站的「错的点」档案，但口头四态判据（负面优先）如实反映——答错多到 weak，下次快照/推荐自然点名，教练不必在收尾时替学习者总结失败。

**完成标志**：N 题口述全部落盘且回流（`oral-attempts.json` 有 N 条新明细、POST 响应 `accepted` ≥ N；热身形态 = 该题在答题站已答）+ 钩子式收尾一句说完 + 下站预告落 `next-hook.json`。

### 收尾开环预告（每次会话的最后一句话；v0.26，#124）

**是什么**：会话收尾不再是终点——站收尾（第 4 步）与微块收尾（微块模式第 4 步）**固定**产出下个微块预告，把「未完成感」主动经营成回归钩子（开环效应：人对没做完的事记得更牢），而不是放任它发酵成债务感。题站会话总结页（答题完成弹窗）显示同一句预告——两端一个口径。

**固定形状**：「下次：EP-XX <考点名> 口述 3 题，约 5 分钟」——**考点 + 动作 + 时长量级**三件齐，不空喊「下次继续加油」。

**口径单源**：预告考点与下一站推荐同判据——收尾前跑 `plan-report --json` 读 `next` 字段（`{ep, name, reason, minutes}`，**与断档无关恒出**；reason 只作教练内部依据，不进预告句）。无可推考点（全掌握）→ 如实收「这轮都拿下了，下次开新篇」，不编预告。

**落盘**：写 `study/records/next-hook.json`（单条覆写 + `leftAt` 真实时间戳，模板与语义见 [`contracts.md`](../../../../references/contracts.md) 契约二「下站预告」）。微块不开站不建记录，但这个文件例外——它是跨会话的记忆，不是站档案。

**下次开场认领**（第 0 步第 4 条）：有未认领预告且考点未掌握 → 开场报数后一句认领「上次说好下次练 X，今天从它开始？」——认领是建议不是指令，学习者改主意就照改；考点已掌握 → 静默跳过（预告过期不是欠账）。

**语气红线**：钩子式、零催办——预告句只说「下次可以做什么」，不出「还没做 / 该做 / 欠着 / 落后」类字样（与微块收尾同一条红线）。

### 重排计划（v0.27，#121；学习者说「重排计划 / 按我实际速度重新排 / 排期排不下了」才进）

**是什么**：重启排期不再手写——手写理想排期的教训（spec #118：排期假设 ≤1 天/站 vs 实测 2.6 天/站，红字债从第一天滚动累积），重排改由**计划生成器**按实测速率生成：剩余 N 单元 × X 天/单元 ÷ 活跃率 → 日历天数，每个剩余单元落一个合理 `plannedDate`，考期只做可行性对照。生成器是工具链命令（agent 代跑，可跑不可派）；写入口径（done 单元不动、先预览后写回）单源 [`contracts.md`](../../../../references/contracts.md) 契约三「重排」节。

**硬前置**：主题有 `plan.json`（无计划文件不发明计划）；实测速率有来源——学习者认可的实测值（复盘/对账口径，如 2.6 天/站、活跃率 0.54）或 done 历史可派生（生成器自己会派生，缺数据时明确报错不猜）。

1. **取速率与活跃率**：优先用学习者给的实测值显式传（`--days-per-unit` / `--activity`）；没有就先跑 `plan-report --json` 看速率外推段，或直接让生成器派生并在预览里报来源。
2. **预览**：先出预览件到主题外（如 `/tmp`），不碰主题文件：
   ```bash
   node apps/quiz-app/scripts/plan-generate.mjs --theme "$THEME" \
     --days-per-unit <实测> --activity <活跃率> [--margin 0.25] --interleave \
     --out /tmp/plan-preview.json
   ```
   `--interleave` = 硬算/概念交错（轻重按排布表深度列代理：掌握=重、理解/了解=轻；轻先行交替，不再「概念前置、硬算后置」——09-15 手工重排的教训是末段硬算+记忆双高峰）；`--margin` 加余量（剩余站更重时 0.2~0.3，复盘口径）。
3. **给学习者看数学，点头才写回**：报生成器的公式行（「N 单元 × X 天/单元 ÷ 活跃率 Y → Z 天（起 → 止）」+ 对照考期富余/缺口天数）与排期表；学习者认可后去掉 `--out` 重跑即写回主题 `plan.json`（契约三读-改-写）。**排不进考期**（生成器 exit 1 附全算术）→ 如实转达缺口与考期内可容纳的最大速率；缩量 / 降余量 / 提活跃率是学习者的拍板，**绝不静默压缩速率把不可行排成可行**。
4. **复核**：写回后 `plan-report --theme "$THEME"` 直读主题文件立即生效（首页/全景的站点 UI 要等下次 build——产物时滞属预期，契约三）。

**语气红线**：重排是「按你的真实节奏排」不是「你落后了」——零催办，与断档回归后移建议同一条线；交错轻先行是保小胜，不是给欠账排序；done 单元一动不动（完成是事实）。

### 第 0 步 · 开场纪律（进站续站都先走，四条缺一不可）

陪练会话的第一句话不是「今天想学什么」，是教练先报数——用户不用自己想从哪开始，也不该复习优先级被新鲜感劫持。

1. **开场先报「今天最该练 + 为什么」**：跑全景报告（`mastery-report --panorama --json`，[`state.md`](../../../../references/state.md) §3）取浓缩版——汇总行（已讲 X/N · 已练 Y/N · 已掌握 Z/N）+ 最弱考点（`mastery-report` 的 weakRanked/档案错因）+ 未毕业错题数 + 到期卡数。开场一段话报「今天最该练 <一个具体动作>，因为 <数据理由>」，然后给建议的当天范围（与第 1 步的排班衔接）。**建议基于数据不基于印象**——这是推荐算法同一套判据，只是把执行时机提前到陪练开场（10 条优先级链不变）。**有知识图时（`--graph` 的 `graph.weakOrdered`）推荐序尊重前置**：前置概念还没掌握就先补它——理由照实点名（「EP-02 还弱，但它的前置 EP-01 暂存区也没掌握，先补 EP-01」），依赖顺序优先于清单顺序（state.md §3）。
2. **弱考点软坚持**：开场报出的弱考点（未毕业错题 / mastery weak）没清完 → 先清弱考点再讲新内容，这是默认排班；**不硬锁**——用户执意跳过就尊重选择，但在当站记录留痕一行：`- 跳过未清：EP-03 chmod（<用户给的原因，没有就写「用户优先学新内容」>）——下一站开场再清`（写在「错的点」节末尾）。档案不说谎，也不拦路、不说教。
3. **到期概念先口头抽背**：快照 `srsDue > 0` → 正题开始前先抽背 2-3 张到期卡的**概念**（口头问卡正面，不翻 app）：答对过、答错当场纠一条 + 记进当站「错的点」并把该卡的概念排进本站待办。抽背是拦遗忘变成缺口的第一道闸，两三张、几分钟，不展开成讲课。**每次抽背问答当场追加口头流水一条并实时回流答题站**（`oral-attempts.json` + POST `/api/oral-attempts`，source `recall`，写入口径见 [`contracts.md`](../../../../references/contracts.md) 契约二）。
4. **认领上次的预告**（v0.26 #124）：探测见 `study/records/next-hook.json` 有未认领预告（[`state.md`](../../../../references/state.md) §7）且该考点未掌握 → 开场报数后一句认领「上次说好下次练 <EP-XX 考点名>，今天从它开始？」（口述 3 题微块或并入本站待办均可，学习者点头为准）。考点已掌握 → 静默跳过，不提「还欠着一个」；无预告文件 → 什么都不说，零变化。

倒计时口径不变：只消费 MISSION.md 声明的 `deadline`（缺失亮 ⚠ 引导补，见 [F11](F11.md) 第 1 步），教练不自设催办节奏、不替用户排冲刺日程。学习计划自带的 `plan.json` `deadline` 是**计划期限不是考期**（state.md §3 两行口径，不互替），F10 不拿它催办——只按契约三维护单元状态。

### 第 1 步 · 开站前读事实（凭记忆开讲是大忌）

1. **讲到什么深度**：主题包 MISSION.md 的**考点排布表**说了算（深度、题型、day 全在表上）；没表先按 [F2](../flows.md) 第 1-2 步补，或向用户声明按材料自拟大纲。
2. **本站讲哪些**：从排布表圈**最少必要考点**（coach.md §8：缺一项就动不了，多余全砍）；可对题库按拟讲考点做词频统计——高频优先、冷门敢跳。
3. **概念从哪来**：主题包 `lessons/*.html` 与 RESOURCES.md。讲时标文件 + 位置；材料未覆盖要直说，自造类比标「自造」。
4. **用户在哪**：Step 1 快照看该主题正确率（90%+ 走快节奏）；已有 F4 串讲产物必读——真实痛点考点别装覆盖。
5. **上次讲到哪**：`study/records/` 有本主题的进行中记录 → 不是开新站，是**续站**，带待办直接进循环。

**当天范围不问用户**：从排布表 day 计划 + 进行中记录推导后给建议（「今天打第 5 站剩的两个考点，行吗」），用户可改——排班是教练的活，问「今天想学什么」是把排班外包给最不该排班的人。开场一段话报本站范围（材料/课程依据 + 考点骨架），然后**直接进考点 1**。

新站先按契约二建学习记录（`status: in-progress`），再进循环；主题有 plan.json 时，本站涉及的计划单元同步**开站**翻 `in-progress`（契约三；无计划文件则跳过）。

### 第 2 步 · 定考法（首跑问一次，之后不问）

| `mode` | 考法一句话 | 详见 |
|---|---|---|
| `quick` 快验 | 每考点从题库取选择题 2-3 道，一道一道答、即时判定，错出变体 | coach.md §6.1 |
| `deep` 深练 | 讲透后先复述再造，定义错误零容忍 | §6.2 |
| `two-step` 两段式 | 每考点先选择题快验、全对后再复述一遍 | §6.3 |
| `adaptive` 按型分配 | 记忆型走选择题 + 死记提示；理解/应用型走复述 + 造 | §6.4 |
| `custom` 自定义 | 用户原话 + 教练解析纪律，存档后原样沿用 | §6.5 |

- **首跑触发**（主题包**无 COACH.md** 时，仅此一次）：只问一个问题——**「怎么考我？」**五个选项如上；教练按排布表构成（符号型/理解型比例）与考期临近度给推荐（选型处境见 coach.md §6 开头）。答案写入 COACH.md（契约一，见 [`contracts.md`](../../../../references/contracts.md)）。
- **开新站**：读 COACH.md 默认沿用 + 一句话确认（「还按 deep 考你？」）。
- **续站**：沿用该站记录 frontmatter 的 `mode`，不重问。
- **用户喊换模式才重选**：更新 COACH.md 与进行中站的记录。

为什么只问一次：教学模式是偏好不是每站变量，重复问等于把教练的记性外包给用户。

### 第 3 步 · 陪练循环（一次只吃一个考点）

一轮五步**讲透 → 考 → 复述 → 纠 → 造**，顺序不可换，骨架与各步标准见 coach.md §2；本 flow 钉节奏与落盘：

- **一次只讲一个考点**，讲完不预告下一个——并进两个，两个都讲不透。
- 讲解一律三段式（quick 短的是篇幅不是结构，§3），口吻与台阶守 §3.5-3.9：说话腔、先地图后路程（成员多先给全家福，亲戚概念不塞半路）、一次只上一个新东西、讲一块停一拍、重讲换说法、拆解块贴「是什么/为什么/怎么用」可见标签；符号型考点开讲第一句明说「**这是要死记的**」（§4）；每考点落一句锚点金句，抽象配类比、并列配助记（§5）。
- 换说法两轮仍讲不通、或机制天然是图（流向/层次/包含/对比）→ **图解降维重讲**（coach.md §3.10）：终端 ASCII 图内嵌即时画，复杂机制产 HTML 图解卡落 `study/notes/`（随 build 上站）；画懂不算过，回「考/复述」验证。
- **考**按本站 mode 走（§6）：选择题即时判定 ✅/❌ + 一句理由（只给题面 + 选项，答完才解释）；复述与造按 §6.6 判定；**案例型考点**（DFD/ER/UML/算法/设计模式一类主观大题）走 §6.7 案例通道——真题风格原创大题 + 解题范式四步带练 + 评分点判定，判定进口头答题流水，范式卡沉淀 `study/notes/`；定义错误零容忍，当场打断（§7）。
- **每过完一个考点，立刻增量写盘**到本站记录：已过考点追加一行（考点 + 金句）、错的点记上、待办划掉、**口头问答追加进流水并实时回流答题站**（v0.26 起：写 `oral-attempts.json` 的同一笔作答顺手 POST `/api/oral-attempts`，网站全景/掌握度刷新即见，不用等 rebuild；写入口径单源在 [`contracts.md`](../../../../references/contracts.md) 契约二）——不等站收尾。会话中断、跨天重启，进度都在盘上；所有模式一视同仁（quick 也写档案、也能续站）。

### 诊断纠偏入口（循环随时可插）

用户说「学了没用 / 记不住 / 想放弃 / 我卡住了」类输入：照 coach.md §9 对照表定位根因 → 给**一句用户下一分钟就能动手执行的话** → 从诊断出的那一环接回陪练循环。症状对不上表，先问一句再猜——猜错的诊断比没有诊断更糟。

### 第 4 步 · 收站与交棒

1. 本站考点全过 → 记录改 `status: done`，COACH.md 更新 `current-station`；本站恰好讲完的计划单元同步**收站**翻 `done` + 补当天真实 `doneDate`（契约三）。
2. **阶段笔记**（仅含复述或造的模式：deep / two-step / adaptive / custom）：阶段考点全过后**主动**生成到 `study/notes/`（html：总结 + 自检题），不等用户开口；quick 只写档案不产笔记（快验只建再认，§6.1）。笔记过 `pnpm run scan` 随 build 上站。
3. **主动交棒 F3**：阶段教完直接推「去刷这课对应的题集」——教了不验，等于没闭环。
4. **收尾开环预告**（v0.26 #124）：交棒后固定产出下个微块预告（「下次：EP-XX <考点名> 口述 3 题，约 5 分钟」）并写 `study/records/next-hook.json`——形状、判据源与语气红线见上方「收尾开环预告」节，站收尾与微块收尾同款。

### 只干 / 绝不干

- **只干**：教懂、模式化小考、续站、逐考点落盘、阶段沉淀笔记并交棒、收尾留开环预告（`next-hook.json`）、学习者点名时按实测速率重排计划（生成器预览→点头→写回）。
- **绝不干**：在教学对话里**刷题库的题**——成组刷题是 F3 的活，quick 每考点取 2-3 道是「考」不是「练」，即停即走。**不现改教材**——教材修改只在工厂链（F6/F7）。**不替用户写笔记**——笔记是用户复述的再组织，教练只收编格式。

### 学习痕迹住哪：study/ 伞目录（四分法）

```
<主题包>/study/
├── records/          # 进度档案（md，本地不上站）——F10 逐考点写；续站、冲刺都读它
├── notes/            # 阶段笔记 + 图解卡（html，上站）——F10 阶段产出；图解卡 = 讲不通时的图解降维重讲产物（§3.10），任何模式都可产
├── wrong-questions/  # 错题讲解（html，上站）——F4 产
└── sprint/           # 冲刺包（html，上站）——F11 考前冲刺产（归 F11 管，此处只点名）
```

口诀：**学新读教材、内化写笔记、平时查档案、考前背冲刺包**——前三种是积累，冲刺包是收割。上站的 html（notes / wrong-questions / sprint）统一过品牌 scan、随 build 发布；records 只留本地。旧布局的根级 `learning-records/` 照读照报（识别规则见契约二），并提示用户一次性迁进 `study/records/`，不强制。

### 落盘契约（契约一 / 契约二 / 契约三 · 单源在 contracts.md）

COACH.md（契约一：教学模式权威存储 + 教学偏好便签）与学习记录（契约二：`study/records/<NN>-<slug>.md` 的 frontmatter 与正文四节、口头答题流水写入口径、旧格式兼容规则）的模板与合并规则，单源维护在 [`contracts.md`](../../../../references/contracts.md)——本流程落盘、F11 收割抽取、state.md §7 探测识别三方共用。开站建档、逐考点增量写盘、首跑写 COACH.md 前，照 contracts.md 的原文格式写；**此处不另抄格式**——抄两份必漂移。

**计划单元状态维护（契约三）**：主题有 `plan.json` 时，本流程是它单元状态的唯一维护方，四个触发点——**开站**（第 1 步建站记录同时，本站涉及的单元翻 `in-progress`）、**收站**（第 4 步站 done 同时，讲完的单元翻 `done` + 补当天真实 `doneDate`）、**搁置**（用户明确暂停某单元时翻 `paused`；逾期/落后是节奏事实，不自动搁置）、**重排计划**（学习者明确说才进，见上方专节——生成器重写剩余单元 `plannedDate`，不走手工改字段）。plan.json 是主题数据——住 `examples/<theme>/`（含外部主题包路径），agent 直改主题文件、运行期不另存；写入口径（读-改-写、只动 `status`/`doneDate`、重排走生成器、无计划文件整体跳过）单源在 contracts.md 契约三，此处不另抄。

**完成标志**：本站考点全过 + 记录 `status: done` +（有计划的主题）对应单元按契约三收站 +（含复述/造的模式）`study/notes/` 笔记落盘且 scan 零命中 + 已交棒 F3 + 收尾预告落 `next-hook.json`。
