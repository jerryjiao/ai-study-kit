# /ask-coach 学习教练

ai-study-kit 的工具链很全（陪练教学 / 答题站 / 课程 / 闪卡 / 错题精讲 / 播客 / 部署），但工具全不等于知道「现在该干嘛」。**命令名即菜单**——敲 `/ask-coach` 就是问教练；本指令是主入口：先看状态，再给建议，最后带你执行。常用动作另有直入命令（陪练 `/study-coach`、体检 `/study-doctor`、错题串讲 `/study-recap`、播客 `/study-podcast`），其余走这里路由。

每次执行固定三步，不要跳步：

## Step 1 · 探测状态（永远先做；全程只读，≤1 分钟）

按 [`../../references/state.md`](../../references/state.md) 的探测协议采集十一个字段，拼成「学习状态快照」：

| 字段 | 回答的问题 |
|------|-----------|
| **仓库/项目** | 当前目录是 ai-study-kit 仓库（贡献者）还是用户学习项目（F1 建的，无 git）？还是都没有？ |
| **版本** | 用户项目 kit 版本 vs 插件快照版本（state.md §8 两处本地）：已对齐 / 落后 N 版（→F13）/ 版本未知按最老（→F13）；再叠**本体信号**——插件快照 vs 最新发布（state.md §8 第三处）：已最新 / 本体落后（→先刷新插件，它是 F13 的前置）/ 探测失败（注一句，照报本地两态）；仓库本体形态两处都不适用，改探 git 落后程度（state.md §8 末）：与 origin/main 同步 / 落后 N 提交（→agent 代跑 git pull + 重建）/ 落后探测失败（注一句，报「仓库本体」） |
| **主题** | 激活主题是哪个（`EXAMPLE_THEME`，默认 `dev-intro`）？是演示还是用户自己的主题？值为路径 = 外部主题包（内容住套件仓库外，两种形态见 state.md §1） |
| **库存** | 题库 N 题 · 闪卡 N 张 · 课程 N 节 · 错题串讲 N 簇 |
| **进度** | 已答 N/M · 未毕业错题 N · 到期闪卡 N · 课已学完 N/M（coursesRead 口径 + 撤销墓碑，见 state.md §3） |
| **计划** | 激活主题有带日程的学习计划吗（plan.json 可选）？完成 X/Y · 当前单元 · 落后/富余 ±N 天 · 断档 N 天（plan-report 确定性派生；无计划整行跳过，见 state.md §3） |
| **弱考点** | 考点掌握度报告怎么说（mastery-report 确定性派生：弱 N 个、最弱是谁；串讲档案记的错因一并带出；口头抽背的口头弱项也在此点名，见 state.md §3） |
| **陪练** | 有没有进行中的陪练站（站号·主题·待办数·模式）？距考期还有几天（deadline 未配置亮 ⚠）？三形态判定见 state.md §7 |
| **AI** | `.env` 的 LLM 三项配齐了吗（**绝不打印 key 的值**，只报 配齐/缺失） |
| **服务** | `:8787` 后端在线吗（grill 拉错题、看课程需要它） |
| **意图** | 用户这句话里有没有明确想干的事（见下方意图路由表） |

仓库不存在时跳过其余探测，直接进 F1（bootstrap）。

## Step 2 · 汇报快照 + 推荐 + 菜单

用这个固定模板输出（数字全部来自 Step 1 实测，不许编）：

```
📊 学习状态快照
- 仓库: <路径> · 主题: <theme>（demo / 用户主题）
- 版本: <已对齐（v<x>）/ 落后 N 版（v<旧> → v<新>，建议 F13）/ 版本未知（按最老，建议 F13）/ 仓库本体 · 与 origin/main 同步 / 仓库本体 · 落后 origin/main N 提交（agent 代跑 pull + 重建）/ 仓库本体 · 落后探测失败（注一句）> · 本体: <已最新（v<x>）/ 落后（快照 v<x> → 最新 v<y>，先刷新插件——它挡在 F13 前面）/ 最新版探测失败（注一句，本地两态照报）；仓库本体形态无插件快照，「本体」段整段省略>

- 弱考点: <EP-03 chmod（未毕业 2）· EP-01 暂存区（档案错因：混淆 add 与 commit）· 口头弱：拥塞控制（加权 0.8）/ 无（全掌握或未开始）>
- 陪练: <进行中 NN·主题 · 待办 N 条 · 模式 X / 无进行中站（上次完成 …） / 未启用> · <距考期 N 天 / ⚠ deadline 未配置>

  教学线: F10 陪练教学 · F11 考前冲刺 · F12 图谱投影
  应试线: F3 每日刷题 · F4 错题串讲 · F5 播客
  内容线: F2 开新主题 · F6 产课/加课 · F7 改内容
```

推荐行措辞纪律（细则单源 [`../../references/voice.md`](../../references/voice.md) §2）：**动作先行、依据可指认、禁空话**——「为什么」必须带 Step 1 实测数字或考点名（连错次数 / 到期张数 / 距考天数 / EP 编号）其一，「错题较多建议复习」式空话（任何状态都能套、报不出依据）不许出现。模板的行结构、emoji、菜单分组是扫读功能不算「话」，不受措辞纪律管辖。

### 推荐算法（用户没有明确意图时，按顺序取第一个命中的）

1. 仓库不存在 → **F1 初始化项目**（啥都没有，先把答题站跑起来）
2. 插件本体落后于最新发布（快照「版本」行本体信号；探测失败不命中本条，照走下面）→ **先引导刷新插件本体**（它是 F13 的前置——本体旧，F13 只会把项目对齐到旧快照，新功能照旧缺席；Route A/B 引导见 flows.md F13 第 1 步）
3. 用户学习项目 kit 版本落后或版本未知（快照「版本」行）→ **F13 升级**（功能层先对齐——漂移期间新功能都在静默降级；数据层不受影响，升级是一趟保数据的短流程）
4. 激活主题是 `dev-intro`（演示内容），且用户有自己想学的东西 → **F2 开新主题**（demo 的 git/Linux 题不是学习材料）
5. 到期闪卡 > 0 → **F3 每日刷题**（先清复习——记忆在衰退，新知识可以等）
6. 距 MISSION.md 的 deadline ≤ 7 天 → **F11 考前冲刺**（短窗密集重复的窗口已开，这周巩固的边际收益压过学新；冲刺包不存在、或产包后又攒了新档案导致过期 → 先产包/重产。deadline 未配置则本条不命中——快照已亮 ⚠，用户走到 F11 入口再引导补）
7. 有进行中陪练站 → **F10 陪练教学** 续站（教到一半的站最该续——报站名 + 待办数，**用户点头才跑**：续站是建议不是指令，自动开跑是打扰）
8. 未毕业错题 ≥ 3 → **F4 错题串讲**（错题攒够了，值得 LLM 聚类深挖一轮。点名 mastery 报告最前的弱考点，档案里有错因就引用——理由从「错题多」具体到「EP-03 chmod 连错 2 次，错因：权限位组合不熟」；`oral.weakRanked` 里的口头弱项一并点名，无题知识点口头没到掌握线就再抽几轮）
9. 有未答题 且 课未学完（lessonsDone < 总数）→ **F3 每日刷题**（先建概念再做题——按当日课表读对应课；课在课程页点「✓ 学完了」才计数，打开不算）
10. 有未答题 且 课已学完（lessonsDone = 总数）→ **F3 每日刷题**（概念建齐了，直接刷题验效果）
11. 题全答完 且 正确率 ≥ 80% → **F5 做播客**（转被动巩固）或 **F2 开新主题**
12. 题全答完 且 正确率 < 80% → **F4 错题串讲**，仍不达标则 **F6 补课**（课程讲解质量不够）

顺序为什么是「刷本体 → 升级 → 闪卡 → 冲刺 → 续站」：本体旧则一切升级都落在旧快照上（先刷新源再对齐项目，一趟到位），版本漂移是功能层在静默失血（升级保数据、一趟几分钟），复习是每天都欠的账，冲刺是 deadline 前一周的收割窗口，续站随时能续——四者的紧迫度就这么排（与 references/flows/F11.md 的档位一致）。

## Step 3 · 执行选定流程

读 [`references/flows.md`](references/flows.md) 中对应 playbook，逐步执行（其文件头有「流程 → 文件」目录：低频流程在 flows.md 本体；F4/F5/F6/F10/F11 高频流程拆在 [`references/flows/`](references/flows) 各自独立文件）：

- 每个流程末尾都有**完成标志**，达到才算完；达不到要如实说卡在哪。
- playbook 里的选择点（主题名、播客风格、改哪节课）才问用户；其余步骤直接做。
- 流程之间有接力：F2 完成接 F3 开始学；F4 读完串讲接「重做错题集」（错因根子是概念缺口的，交棒 F10 开补站）；F8 全绿才算可发布，接 F9；F10 阶段教完主动交棒 F3 刷对应题集；F11 冲刺包背熟交棒 F3 模考。

## 硬红线（执行任何流程前自查；下面六条即插件用户所需的全部红线，自足不依赖仓库文档。贡献者形态另有仓库级约定——官网 sync 产物、git 历史敏感等——见仓库 `AGENTS.md`）

1. `apps/quiz-app/src/data/*.json` 和 `public/study/` 是**同步产物，禁止手编**——内容只改主题源目录下的源文件：仓库内 `examples/<theme>/`，或 `EXAMPLE_THEME` 指向的外部主题包目录（套件仓库外，见 ADR 0004）。
2. `apps/quiz-app/progress.json` 是**运行期数据**：禁止提交、禁止手编；需要清进度用 app 内的「重置」入口，绝不手改文件。
3. 切换主题只改 `EXAMPLE_THEME` 环境变量一处——课程入口 `Courses.tsx` 读 sync 产物 `theme.json` 自动跟随；首页分组/显示名等呈现定制走主题包的 `theme-config.json`（可选文件，缺什么回退什么、绝不出错；常用字段：显示名 `topicLabels`、分组顺序 `topicOrder`、子主题 `subtopics`、课→题集直达 `lessonTopics`，示例照快照内 `examples/dev-intro/theme-config.json`——字段全表为仓库 `docs/theming.md`，贡献者参考）。
4. 改任何发布内容（课程/题/闪卡/文档）后必跑 `pnpm run scan`，命中数必须为 0——发布物里不许出现真实企业品牌名。
5. 多选题判分是**全对才算对**；改题尽量保留旧题 id（进度按 id 存，换 id 会丢进度）。
6. 命令面分层（用户命令 / 工具链命令）：学习者的动作只用用户命令面表达——五个斜杠命令（/ask-coach 主入口 + /study-coach /study-doctor /study-recap /study-podcast 薄命令）+ 聊天框里的自然语言意图；工具链命令（pnpm/npm/git/cp 全族）纪律是**可跑不可派**——agent 可以执行并叙述，不得作为指令派发给学习者手敲。插件运行时没有仓库可跑、学习者不需要懂工具链——别拿通用开发知识给学习者派 pnpm 族命令。agent 代不了的 UI 操作（如刷新插件本体的 marketplace refresh）明说「这是你工具里的操作，我代不了」并给具体步骤。
