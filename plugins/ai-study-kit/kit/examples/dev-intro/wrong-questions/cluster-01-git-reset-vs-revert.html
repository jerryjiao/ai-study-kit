错题精讲 · git reset vs git revert

对应题目：GIT-007　·　← 返回错题中心　·　相关课程：git 三区与基础命令

这是一道高频错题：「reset 和 revert 都能撤销 commit，区别是什么？」错根是只记住了「都能撤销」，没理解撤销的机制完全不同——一个改写历史，一个追加历史。

一、核心区别表

维度git resetgit revert
本质动作移动分支指针后退新建一个反向提交
历史结果被越过的提交消失原提交 + 反向提交都在
谁的历史被改只影响当前分支给历史追加一条记录
已 push 的提交能用吗禁用（会与团队冲突）推荐（协作安全）
典型命令git reset --hard HEAD~1git revert <hash>

二、用图说话

当前历史：
  A ──▶ B ──▶ C ──▶ (HEAD)

【reset --hard HEAD~1】
  A ──▶ B ──▶ (HEAD)         # C 被"吃掉"，从历史消失
  
【revert C】
  A ──▶ B ──▶ C ──▶ C' ──▶ (HEAD)   # C' 是 C 的反向，抵消 C 的改动

注意：reset 之后 C 真的不在了（除非通过 reflog 找回）；revert 之后 C 还在，只是它的效果被 C' 抵消了。

三、决策流程

     要撤销一个 commit
              │
              ▼
    这个 commit 已经 push 到
    团队共享分支了吗？
              │
        ┌─────┴─────┐
       否            是
        │             │
        ▼             ▼
    git reset     git revert
  (本地安全)    (协作安全)
        │             │
        ▼             ▼
  历史改写      历史追加
  别人看不到    别人能看到「撤了」

四、易错警示

错根 1：以为「reset 和 revert 效果一样，可以互换」。

真相：机制完全不同。reset 改写历史（指针后退），revert 追加历史（反向 commit）。对团队来说，前者是「假装没发生」，后者是「明确告诉大家我撤了」。

错根 2：在团队共享分支上用 reset --hard 撤销已 push 的提交。

真相：你改写了本地历史，下次 push 会与远端冲突，其他同事 pull 下来会出现重复提交或丢失改动。已 push 的提交，一律用 revert。

记忆锚点：「reset 是后悔药，revert 是更正声明」。后悔药只能自己吃（本地），更正声明要贴公告栏（团队都能看）。

五、变体训练

以下是题 GIT-007 的变体，验证你是否真理解了：

变体 1：你在团队分支 main 上不小心提交了一个含密码的文件，已经 push 了。怎么撤销？

答：git revert <hash>，不要用 reset。另外密码进了 git 历史就算 revert 也还在——需要用 git filter-repo 或 BFG 彻底清除，并轮换那个密码。

变体 2：你在本地实验性分支写了 3 个 commit，发现方向完全错了，还没 push。怎么最快清掉？

答：git reset --hard HEAD~3。本地未 push 的，reset 安全且干净。

变体 3：git revert 之后，原来的 commit 还能用 git log 看到吗？

答：能。revert 不删除原 commit，只是追加一条新的反向 commit。原 commit 还在历史里。
