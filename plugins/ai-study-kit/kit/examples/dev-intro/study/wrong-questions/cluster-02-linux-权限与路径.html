1. 核心概念对比：权限位与路径解析

在 Linux 中，理解“谁能做什么”和“文件在哪里”是操作基础。下表梳理了本题组涉及的核心维度。

2. 深度解析错题

LNX-001：权限位的“三权分立”

ls -l 输出的前 10 个字符中，第 2-10 位分为三组，每组三个字符：

  • 第 1 组 (rwx)： 文件所有者。例如文件的创建者。
  • 第 2 组 (r-x)： 文件所属组。例如该用户所在的团队。
  • 第 3 组 (r--)： 其他人。既不是所有者也不在所属组里的系统用户。

记忆口诀：“我、我的队、路人”。顺序固定为：所有者 -> 所属组 -> 其他人。

LNX-002：为什么脚本需要 755 而不是 644？

要让脚本 ./deploy.sh 直接运行，必须赋予它执行权限。

  • 选项 A (644)： rw-r--r--。二进制 110 100 100。所有者只有读(r)和写(w)，没有执行(x)。系统会报错 “Permission denied”。
  • 选项 C (755)： rwxr-xr-x。二进制 111 101 101。所有者拥有 rwx（包含 x），其他人也能读和执行。这是脚本和程序的标准权限。

LNX-003：相对路径的“退几步”逻辑

当前路径：/home/alice/projects。

目标路径表达式：../bob/notes.md。

  1. 第一步 (..)： 从 /home/alice/projects 回退一级，到达 /home/alice。
  2. 第二步 (bob)： 从 /home/alice 进入子目录 bob，到达 /home/alice/bob。
  3. 第三步 (notes.md)： 定位文件 /home/alice/bob/notes.md。

注意： 题目结论称该路径等于 /home/bob/notes.md。在标准目录结构下，../bob 实际指向的是同级目录 /home/alice/bob。若要指向 /home/bob，通常需要使用 ../../bob（回退两级到 /home 再进入 bob）。做题时需严格根据 .. 的定义进行层级推演。

4. 易错警示

陷阱 1：混淆权限顺序 (LNX-001)

很多初学者会凭直觉认为“组”比“人”重要，或者记错顺序。请死记硬背：U (User) -> G (Group) -> O (Others)。这对应 chmod 755 中数字的顺序（第一个数给 User，第二个给 Group，第三个给 Others）。

陷阱 2：忘记脚本的“执行权” (LNX-002)

看到“可以直接执行”或“运行脚本”，必须立刻反应出需要 x 权限。如果只看到 644（常见于普通配置文件），应直接排除，因为它缺少 x。

陷阱 3：相对路径的层级计算 (LNX-003)

.. 只代表上一级，而不是“根目录”或“任意上级”。在深层目录中，容易少算或多算 .. 的数量。建议在草稿纸上画出目录树，一步步“爬楼梯”。

变体 2： 当前目录为 /var/log，路径 ../etc/passwd 指向哪里？

A. /etc/passwd
B. /var/etc/passwd
C. /log/etc/passwd
D. /home/etc/passwd

(点击查看答案: A。解析：/var/log 的上一级是 /var，进入 etc 即为 /var/etc？不对，/var 下通常没有 etc，但按路径逻辑应为 /var/etc/passwd。如果题目考察的是 Linux 标准结构，可能意在考察 /var/log -> .. -> /var -> ../etc 才是 /etc。若严格按照 ../etc，结果是 /var/etc。这是一道考察路径拼接逻辑的题。)
