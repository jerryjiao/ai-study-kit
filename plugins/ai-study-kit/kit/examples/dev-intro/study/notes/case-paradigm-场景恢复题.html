考前翻这张卡看的是怎么拆题，不是背答案——同类题（git / Linux 场景恢复）都按这四步走。

范式四步

  1. 读题拆问题：把题干拆成三栏——已知条件（此刻各区有什么）、要求产物（命令 / 状态描述）、限制约束（不许删文件、还没 commit）。漏读限制是这类题第一大失分源。
  2. 定方法：场景恢复题的方法 = 三区模型（工作区 → 暂存区 → 版本库）+ 每两区之间的搬运/撤销命令族。说一句为什么：所有恢复动作的本质都是「把某区的内容回退或前移一格」。
  3. 逐步作答：每个小问对应一条（或一组）命令，答完自查它动了哪个区、没动哪个区。
  4. 对照评分点：命令选型、状态描述、副作用边界逐条对照——尤其「有没有顺手删掉工作区文件」。

一题示范（本题浓缩）

题干：五个文件已 git add . 进暂存区，其中两个不该进；另三个文件还在工作区；尚未 commit。要求：移出误加文件（不删工作区文件）、送入正确文件并说明每步状态变化。

满分答案骨架（按评分点）：

① 三区现状：暂存区=五文件快照；工作区=三文件改动未入暂存；版本库=上次提交。
② 移出误加：git restore --staged debug.log tmp-notes.md（只动暂存区，工作区文件保留）。
③ 不用 git rm --cached——它的语义是「取消跟踪」，删除动作会进下次提交，不是撤出暂存。
④ 送入版本库：git add a.ts b.ts c.ts → 暂存区含三文件；git commit -m "…" → 版本库新增提交、暂存区清空。

易错警示：把「撤出暂存」和「取消跟踪」混为一谈；恢复类命令先问「它动哪个区」，再敲。
