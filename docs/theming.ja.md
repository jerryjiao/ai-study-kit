# テーマ表示設定（theme-config.json）

[简体中文](theming.md) · [English](theming.en.md) · [Español](theming.es.md) · [Русский](theming.ru.md) · **日本語**

クイズアプリの表示層のカスタマイズはすべて——ホームの並び順、表示名、サブトピックの展開、ソースバッジ、核心／応用の層、出題ポイントの深さバッジ、カードの配色——テーマパックの `theme-config.json` に住んでおり、**アプリのコードを一切触る必要がありません**。このファイルは完全に任意です：提供しなくてもアプリはフォールバックのセマンティクスで動作し、決してエラーになりません。

完全なサンプルは [`examples/dev-intro/theme-config.json`](../examples/dev-intro/theme-config.json) を参照してください。

---

## 同期パイプライン

`sync-examples.mjs` は dev / build / test の前に `examples/<theme>/theme-config.json` を `apps/quiz-app/src/data/theme-config.json` へコピーします（同期成果物なので手で編集禁止。編集しても上書きされます）。このファイルがないテーマには空の設定 `{}` が同期され、アプリは普通に動きます。

---

## フィールド一覧

すべてのフィールドを省略できます。ないものはフォールバックします：

| フィールド | 型 | 役割 | 未設定時のフォールバック |
|---|---|---|---|
| `topicLabels` | `{topicId: 表示名}` | 大分類の UI 表示名（topic id はデータ層の安定した識別子で、表示は常にそれを経由する） | topic id をそのまま表示 |
| `topicOrder` | `[topicId]` | 大分類の学習順（易しいものから深いものへ）。リストされていない topic は末尾へアルファベット順 | すべてアルファベット順 |
| `subtopics` | `{topicId: [subtopic のフルネーム]}` | 出題ポイントの深さ順のサブトピック表。設定した大分類はホームで第二階層のナビゲーションを展開 | 展開しない（大分類カード 1 枚） |
| `sourceLabels` | `{source: 短い名前}` | 問題カードのソースバッジの表示名 | source をそのまま表示 |
| `sourceLayers` | `{source: 核心\|拓展}` | ソース → 学習優先度の層へのマッピング | 層の概念なし（`layerOf` が null を返す） |
| `layerTopics` | `[topicId]` | 層の概念を持つ大分類（演習ページの層 chips／ホームの深さバッジのスコープ） | どのテーマにも層なし |
| `lessonTopics` | `{"<lesson のファイル名>": topicId}` | レッスン → 問題セットへの直行マッピング：コースページで一つのレッスンを学び終えた後の「このレッスンの問題を解く」ボタンが、これを使って対応する問題セットへ遷移します | ファイル名（`.html` を除く）がたまたま問題バンクの topic と同名なら直結、そうでなければジャンプボタンを描画しない |
| `epDepth` | `{考点のベース名: 掌握\|理解\|了解}` | サブトピックの出題ポイントの深さバッジ。表引きの前に分割チャンクの接尾辞を剥がす（`线性表一` → `线性表`） | バッジなし |
| `topicStyles` | `{topicId: {cls, childCls, icon}}` | 大分類カードの配色（Tailwind class 文字列）＋アイコン名 | デフォルトスタイル |

最小構成はこんな形です（二つの大分類の表示名と順序だけ変える）：

```json
{
  "topicLabels": {
    "git-basics": "Git 基础",
    "linux-commands": "Linux 命令"
  },
  "topicOrder": ["git-basics", "linux-commands"]
}
```

## フォールバックのセマンティクス（設計原則）

設定は**純粋な追加**です：各フィールドは独立して効き、どんな欠落にも定義済みのフォールバックがあり、設定が不完全だからといってエラーになることは決してありません。核心の口径は**計画内**（主進捗）です——`isPlanned = ソース層 ≠ 拓展`：`sourceLayers` の設定がないテーマではすべての問題が自動的に計画内と数えられ、進捗の分母／ホームのカウント／ランダムプールの口径は変わりません。

---

## アイコン名

`topicStyles.icon` には文字列の名前を書きます（`"Boxes"`、`"Layers"` など）。アプリ側は `apps/quiz-app/src/lib/themeConfig.ts` のホワイトリストマッピング表で lucide コンポーネントへ解決します——設定はデータ、コンポーネントはコード、マッピング表が橋です。収録されていない名前は `Boxes` にフォールバックします。選択できるアイコンを増やすにはその表を変更します（tree-shaking の制約により、ホワイトリスト内のコンポーネントだけがバンドルされます）。

---

## サブトピックの命名規約

`subtopic` のフルネーム = `{topicId}·{表示名}{漢数字の分割チャンク接尾辞}`。例：`git-basics·工作流`、出題数が多く分割するときは `xxx·线性表一` / `xxx·线性表二`。接頭辞は完全な ASCII 識別子（`[a-z0-9-]`）でなければならず、区切りには `·` `:` `-` の三つの過去の書き方をサポートします——UI が接頭辞を剥がすときは ASCII 識別子を境目にし、topic 名自身のハイフンを誤って区切りと見なさないようにします。同じベースの分割チャンクは漢数字の順に並びます（一<二<…<十一。表引き方式。`localeCompare` は漢数字に信頼性がないため）。

---

## 層（核心／応用）

層は問題の**学習優先度**の属性で、source から派生し、問題カードのバッジ＋演習ページのフィルタ chip として表示されます。ナビゲーションの次元は占めません。設定パネルの「応用演習」スイッチ（デフォルトでオフ）がオフの間、層の概念は全体として存在しません：chips は描画されず、`&layer=` の直行リンクは無効になり、すべてのリストには計画内の問題だけが含まれます。オンにすると「デフォルトは核心、chip は三状態（すべて／核心／応用）」の挙動に戻ります。計画内が 0、応用が 1 以上のサブトピックのブロックは「純応用ブロック」です——スイッチがオフのときはブロック全体が姿を消し、オンのときはグレーの「応用 N」バッジ付きで表示されます。
