# Настройка отображения темы (theme-config.json)

[简体中文](theming.md) · [English](theming.en.md) · [Español](theming.es.md) · **Русский**

Вся настройка отображения тренажёра — порядок на главной странице, отображаемые имена, раскрытие подтем, значки источника, слои «ядро/расширение», значки глубины пунктов экзамена, цвета карточек — живёт в `theme-config.json` пакета темы, **трогать код приложения не нужно**. Файл полностью необязателен: без него приложение работает по резервной семантике и никогда не падает.

Полный пример — [`examples/dev-intro/theme-config.json`](../examples/dev-intro/theme-config.json).

---

## Конвейер синхронизации

Перед dev / build / test `sync-examples.mjs` копирует `examples/<theme>/theme-config.json` в `apps/quiz-app/src/data/theme-config.json` (артефакт синхронизации: править вручную запрещено — правки будут перезаписаны). Темы без этого файла синхронизируются пустой конфигурацией `{}`, и приложение работает как обычно.

---

## Обзор полей

Любое поле можно опустить — на что-то не заданное приложение откатывается к резерву:

| Поле | Тип | Назначение | Резерв без настройки |
|---|---|---|---|
| `topicLabels` | `{topicId: отображаемое имя}` | отображаемые имена разделов в интерфейсе (topic id — стабильный идентификатор слоя данных; всё отображение идёт через него) | показывается исходный topic id |
| `topicOrder` | `[topicId]` | порядок изучения разделов (от простого к сложному); не перечисленные topic падают в конец по алфавиту | всё по алфавиту |
| `subtopics` | `{topicId: [полное имя подтемы]}` | список подтем в порядке пунктов экзамена; настроенные разделы раскрывают навигацию второго уровня на главной | не раскрывается (один раздел — одна карточка) |
| `sourceLabels` | `{source: короткое имя}` | отображаемые имена значков источника на карточках вопросов | показывается исходный source |
| `sourceLayers` | `{source: 核心\|拓展}` | отображение «источник → слой приоритета обучения» (значения 核心/拓展 — «ядро»/«расширение») | понятия слоёв нет (`layerOf` возвращает null) |
| `layerTopics` | `[topicId]` | у каких разделов есть слои (область действия чипов слоёв на странице отработки / значков глубины на главной) | ни у одной темы нет слоёв |
| `lessonTopics` | `{"<имя файла урока>": topicId}` | прямое отображение «урок → набор вопросов»: после прохождения урока кнопка «отработать вопросы этого урока» ведёт на соответствующий набор | прямая ссылка появляется, только если имя файла (без `.html`) совпадает с topic из банка вопросов; иначе кнопка не отображается |
| `epDepth` | `{базовое имя пункта: 掌握\|理解\|了解}` | значок глубины пункта экзамена у подтемы; перед поиском отрезается суффикс блока (`线性表一` → `线性表`). Значения 掌握/理解/了解 — «владение/понимание/знакомство» | значка нет |
| `topicStyles` | `{topicId: {cls, childCls, icon}}` | цвета карточки раздела (строки Tailwind-классов) + имя иконки | стиль по умолчанию |

Минимальная конфигурация выглядит так (меняются только отображаемые имена и порядок двух разделов; значения в примере — данные темы, оставлены как в исходном файле):

```json
{
  "topicLabels": {
    "git-basics": "Git 基础",
    "linux-commands": "Linux 命令"
  },
  "topicOrder": ["git-basics", "linux-commands"]
}
```

## Семантика отката (принцип дизайна)

Конфигурация **чисто аддитивная**: каждое поле действует независимо, у любого отсутствия есть определённый резерв, и неполная конфигурация никогда не приводит к ошибке. Центральное понятие — **запланированность** (основной прогресс): `isPlanned = слой источника ≠ 拓展 (расширение)`. Для темы без настройки `sourceLayers` все вопросы автоматически считаются запланированными — знаменатель прогресса, счётчики главной страницы и пул случайных вопросов не меняются.

## Имена иконок

В `topicStyles.icon` пишется строковое имя (например, `"Boxes"`, `"Layers"`); на стороне приложения оно через таблицу белого списка в `apps/quiz-app/src/lib/themeConfig.ts` разрешается в компонент lucide — конфигурация это данные, компоненты это код, а таблица — мост между ними. Незнакомое имя откатывается на `Boxes`; чтобы расширить набор иконок, правьте именно эту таблицу (из-за tree-shaking в бандл попадают только компоненты из белого списка).

## Соглашение об именовании подтем

Полное имя `subtopic` = `{topicId}·{отображаемое имя}{суффикс блока на китайских цифрах}`, например `git-basics·工作流`, а при большом объёме вопросов с разбиением на блоки — `xxx·线性表一` / `xxx·线性表二`. Префикс обязан быть цельным ASCII-идентификатором (`[a-z0-9-]`); разделителем допускаются три исторических написания — `·` `:` `-`. Интерфейс отрезает префикс по границе ASCII-идентификатора, чтобы дефис внутри самого имени topic никогда не приняли за разделитель. Блоки с одной базой сортируются по китайским порядковым числительным (一<二<…<十一, через таблицу поиска — `localeCompare` для китайских цифр ненадёжен).

## Слои (ядро / расширение)

Слой — атрибут **приоритета обучения** вопроса, производный от его source; отображается как значок на карточке + фильтрующий чип на странице отработки и не занимает измерения навигации. Пока переключатель «расширенная отработка» в панели настроек выключен (по умолчанию), понятие слоя в целом не существует: чипы не отрисовываются, прямые ссылки `&layer=` не работают, все списки содержат только запланированные вопросы; после включения возвращается поведение «по умолчанию ядро, чип на три состояния (все / ядро / расширение)». Блок подтем с 0 запланированных и >0 расширенных вопросов — «чисто расширенный блок»: при выключенном переключателе он целиком невидим, при включённом показывается с серым значком «расширение N».
