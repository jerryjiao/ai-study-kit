# 知识图谱走 knowflow 投影桥，学习状态不入知识库

2026-09-14 grill 重审 09-13 拒绝的 DeepTutor Memory Graph 后拍板：知识（概念与连线）住外部知识库 knowflow（节点页 + wikilink → graph.json），学习状态（作答 / 复习 / 掌握）住本仓信号源（progress / SRS / 口头答题流水）；掌握度永远现算，经一份**只读投影文件**（节点→状态）单向流向知识图谱供着色与导航，绝不回写知识页。与 DeepTutor 自身架构同构——其 ConceptGraph 与 LearningStore 分家、靠 knowledge_point id 对接，掌握度也是只算不存的纯函数（近期加权正确率 + 置信度封顶），且其学习状态存储因高频写入与并发已从 JSON 文件演进到事务化存储：学习状态和低频人工审阅的知识文件的工程需求根本不同。

## Considered Options

- **状态也入 knowflow**（页面 frontmatter 或并行状态文件）——拒：DeepTutor 无此先例；两处真源会打架（题库判掌握、页面记还弱，听谁的）；多端合并语义得在 markdown 仓库重造一遍；knowflow 其他用户（如 flowtest）背上用不着的学习机制。
- **两项目融合一体**——拒：DeepTutor 单项目内部也拆知识 / 状态 / 记忆三套存储，仓库边界不是重点、**存储边界才是**；合仓只增加耦合，把两边开源用户互相绑定。
- 分界规则：功能属于「知识长什么样」→ knowflow；「你学得怎么样」→ ai-study-kit；「把状态标到知识上」→ 桥（两侧各出一半）。

## Consequences

- 本仓与 knowflow 之间新增**唯一跨仓契约**：投影文件 schema（v0.14 spec 落地），除此之外两仓零耦合。
- 摄取不接（形态 A）：学习者手动用 knowflow 采集合成，本仓只消费其 graph.json；无图或无映射时全部图功能静默降级为纯考点口径。
- 考点节点映射与口头答题流水都是个人学习数据，守 ADR-0002 边界（不上站、不提交）。
- 掌握度判据 v1.1（题 + 闪卡双通道）不动；口头流水只服务无题节点与「练过」信号，不回改已有四态判据。
