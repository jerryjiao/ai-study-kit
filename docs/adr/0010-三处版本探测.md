# 三处版本探测：网络探测进快照 Step 1（version.json 产物 + 三站时机 + 软失败 + URL 可覆盖）

2026-09-28 命令面 spec（#99，grill Q4 拍板 ①+Ⅰ）定案。背景（假绿）：kit 版本此前只比两处本地文件——用户项目 `kit/kit-version.json` vs 插件快照 `<插件根>/kit/kit-version.json`（ADR-0006）——插件**本体**落后于最新发布时两处照样相等，快照报「已对齐」。活例：发起 grill 时本地插件 0.21.0、仓库已发 0.22.0，主入口一路报绿；学习者拿着旧版本以为已是最新，漂移期间的新功能全部静默缺席。拍板补**第三处**：探官网版本产物「最新发布」，作为快照「版本」行的本体信号。

决策四条：

1. **版本真源唯一，产物是官网 version.json**：`apps/site/scripts/gen-version.mjs` 在站点构建（prebuild）时从根 package.json 写 `apps/site/public/version.json`（`{"version":"<版本>"}`，产物 gitignored）。零手工同步——发版改根 package.json，push main 触发 Pages 部署，产物自动跟上；与插件 `kit-version.json` 同构，判读按号比较不做语义化（落后与否优先读 `<插件根>/CHANGELOG.md` 版本序列：快照早于最新发布、或最新发布不在序列里 = 本体落后；快照晚于最新发布 = 未发版开发态 = 本体最新）。
2. **探测时机钉死三站，其余场合不探**：① /ask-coach Step 1（快照「版本」行本体信号——它是推荐算法第 2 条「先引导刷新插件本体」的眼睛）；② F13 第 1 步**复探**（本体落后 → 在第 1 步停下不重拷，绝不把项目对齐到旧快照；按安装形态分叉引导——Route A 明说「刷新插件是你工具里的 UI 操作，我代不了」+ marketplace refresh 步骤，Route B 幂等重跑安装协议）；③ 体检版本行。网络探测有成本，三站 = 快照 / 升级 / 体检各一次，不许蔓延。
3. **全部软失败**：超时 / 解析失败（`latest=unknown`、非 JSON、无 `version` 字段）→ 注一句「最新版探测失败」，照报本地两态，**绝不报错、绝不阻塞**——快照「只读 ≤1 分钟」的离线性不因网络破；推荐算法对探测失败不命中「先刷新」条，照走后续。
4. **URL 可用环境变量覆盖**：`ASK_KIT_VERSION_URL`（默认 `https://aistudykit.dev/version.json`）。演练桩（`file://` curl 直读，不出网）与离线内网自托管两用，不需要为测试留后门代码。

## Considered Options

- **维持两处本地比较（现状）**——拒：假绿不可见——本体落后时两处本地恒报「已对齐」，第三处的缺失让「最新发布」这个事实在产品里无人能报。
- **只进 F13 升级、不进快照**——拒：快照是推荐算法的眼睛；本体落后排在「项目 kit 落后 → F13」**之前**（它是 F13 的前置），快照不报则推荐不会引导「先刷新」，学习者仍从旧本体出发绕远路。
- **npm registry / GitHub Releases API 等第三方取数**——拒：版本真源是根 package.json，第三方接口多一跳且引入 token/限流变量；官网 Pages 本就随 push main 部署，产物挂自家域名零新基础设施。
- **探测失败当红项报**——拒：站点故障或断网会阻塞每天的学习入口——把「最新发布信号缺席」升级成「快照不可用」，代价与收益不成比例；软失败让网络问题只损失第三信号本身。
- **每次显示版本都探**——拒：出网探测有时间与依赖成本，处处探 = 处处等超时；三站已覆盖「看见（快照）、行动（F13）、复查（体检）」全部决策点。

## Consequences

- 发版链新增隐含步骤：version.json 线上生效依赖 push main 触发 Pages 部署——发布没部署完，全体用户第三处软失败（注一句，本地两态照报），不阻塞任何流程。
- 插件用户拿到第三信号要等下一次发版随插件分发（skill 文档改动随版本走）；本 ADR 随 spec #99 收口落地（v0.22.0 之后的首个发版）。
- F13 语义增强为「复探过才动 kit」：停在复探时 kit / progress / 主题分毫不动；行为由演练器 `--scenario=stalled` 断言面锁死（scripts/drill/check-upgrade.mjs，spec #55 行为级验收面先例）。
- 推荐算法插条：本体落后 → 先引导刷新插件本体，插在「项目 kit 落后 → F13」之前——刷新源再对齐项目，一趟到位。
- 仓库本体形态（checkout 当学习项目用）没有插件快照，第三处不适用——该形态探 git 落后程度（HEAD vs origin/main），同一软失败协议（state.md §8 末，spec #99 收官小项②）。
- 离线 / 内网用户：探测失败注一句照常使用，零功能损失，仅最新发布信号缺席。
