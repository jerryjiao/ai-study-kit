# Study Coach · `/ask-coach` 学習コーチコマンド

[简体中文](ai-study-kit.md) · [English](ai-study-kit.en.md) · [Español](ai-study-kit.es.md) · [Русский](ai-study-kit.ru.md) · **日本語**

ai-study-kit の機能は多い——クイズアプリ、コース、フラッシュカード、間違えた問題のまとめ解説、ポッドキャスト、デプロイ。しかし学習者にとっては、それがかえって負担になります：**今日は結局何をすべきか？** `/ask-coach` はまさにこの問いに答えるものです。リポジトリに同梱されたメインエントリ skill です：一度インストールすれば、毎回の学習はここから始まります。状態を走査し、おすすめを示し、実行に伴走してくれるため、ツールチェーンを暗記する必要がありません。

**コマンド名がそのままメニュー**です。プラグイン ai-study-kit（名前は永久不変）をインストールすると、全部で五つのコマンドが入ります：`/ask-coach` がメインエントリ（状態スナップショット＋おすすめ＋実行の伴走。他のフローはここからルーティング）。さらに直接起動できる四つの薄いコマンド——`/study-coach` 伴走型指導（F10）、`/study-doctor` ワンクリック健康診断、`/study-recap` 間違えた問題のまとめ解説（F4）、`/study-podcast` ポッドキャスト（F5）。コマンド面の全体像と意図ルーティング表は `skills/ask-coach/SKILL.md` にあります。

## インストール

skill のソースはリポジトリの `skills/` 以下にあります（単一の信頼できる情報源：メインエントリ `ask-coach` ＋薄いコマンド四つ `study-coach` / `study-doctor` / `study-recap` / `study-podcast`。薄いコマンドはメインエントリの `references/` を共有します）。インストール経路は二つ：

**① プラグインマーケット（zcode / Claude Code、おすすめ）**：リポジトリ同梱の marketplace マニフェスト（`.claude-plugin/marketplace.json`。`scripts/sync-plugin.mjs` がソースから `plugins/ai-study-kit/` を生成）。クライアントで marketplace `https://github.com/jerryjiao/ai-study-kit` を追加し、`ai-study-kit` プラグインをインストールします——以降の skill の更新はマーケットのリフレッシュで届き、**手動での再インストールは不要**です（バージョンはリポジトリの release に追従）。**プラグインの更新後、古いプロジェクトで `/ask-coach` を開くとバージョン差が報告され、F13 アップグレードへ誘導されます**（データを守り、不足を補完。F13 を参照。kit スナップショットは `kit-version.json` で自らのバージョンを報告）。**プラグイン名は生涯 ai-study-kit、コマンド名は ask-coach 一族です**（2026-09 の v0.13 で `/ai-study-kit` から改名。マーケット名は変更できないためプラグイン名はそのまま）。

**② 手動インストール（`~/.agents/skills/` を認識する任意のクライアント）**：

```bash
# ai-study-kit リポジトリのルートで実行（五つの skill を全部インストール。薄いコマンドはメインエントリの references/ に依存）
pnpm run skill:install          # ~/.agents/skills/{ask-coach,study-coach,study-doctor,study-recap,study-podcast} へコピー
pnpm run skill:install -- --link   # シンボリックリンク版（リポジトリの git pull に追随して自動更新）

# その他のクライアント：対象ディレクトリを指定
bash scripts/install-skill.sh --dest ~/.claude/skills

# アンインストール
pnpm run skill:uninstall
```

インストールしたら CLI を再起動（または新しいセッションを開き）、`/ask-coach` と入力するだけです。インストールしなくても使えます：agent に直接 `skills/ask-coach/SKILL.md` を読ませて同じことをさせるだけです。

## どう動くか

毎回の呼び出しは三つのステップ固定です：

1. **状態の検出**（読み取り専用、1 分以内）——テーマ、問題／カード／コース／まとめ解説の在庫、回答進捗、未卒業の間違えた問題、期限が来たフラッシュカード、完了したレッスン、口頭試問で弱い項目（回答履歴から派生）、伴走ステーションと試験日、AI 設定、バックエンドのオンライン状態、kit のバージョンドリフト（ユーザープロジェクト vs プラグインスナップショット。遅れかバージョン不明なら F13 アップグレードへ誘導、下記参照）；知識グラフの場所が渡されていれば、グラフのシグナルも（ノードの習得度四状態、前提関係。F12 を参照）。
2. **報告＋おすすめ**——スナップショットの表一枚＋理由付きのおすすめアクション一つ＋番号付きメニュー。
3. **実行の伴走**——選ばれた後は `skills/ask-coach/references/` 内の対応フローの playbook に沿って一歩ずつ進め、終わったら「完了の目安」で照合して受け入れます。

明確な意図がないとき、おすすめは順に最初に当てはまったものを取ります：環境項目（バージョンドリフト）は学習項目より先——機能層を先に揃え、データ層には影響しません。学習系の先頭は「フラッシュカード → スプリント → ステーション再開」です。復習は毎日返すべき借り、スプリントは試験一週間前の刈り取りウィンドウ、ステーションはいつでも再開できます。完全な 11 条件とそれぞれの理由は `skills/ask-coach/SKILL.md` の「おすすめアルゴリズム」にあります。

## 十三のフロー

十三のフローは四つのラインでグループ分けされ、番号がそのままメニューです：**教学ライン** F10 伴走型指導 · F11 試験直前スプリント · F12 ナレッジグラフ投影；**試験対策ライン** F3 毎日の問題演習 · F4 間違えた問題のまとめ解説 · F5 ポッドキャスト作成；**コンテンツライン** F2 新テーマを開く · F6 コース生成／追加 · F7 コンテンツ変更；**運用ライン** F1 プロジェクトの初期化 · F13 アップグレード · F8 検証とリリース · F9 デプロイ。各フローの playbook（目的／前提／手順／完了の目安）は `skills/ask-coach/references/` にあります——F1–F13 の細則はそこが単一の信頼できる情報源で、本文は案内だけで複製しません。

さらに**健康診断**（`/study-doctor`。四つの検証ゲート＋環境検出の一括オーケストレーション）と**診断**の二つの運用エントリがあります：前者は赤項目のあるレポートと修正順序を出し、後者は進捗が同期しない、コースが 404、CLI が設定エラーを吐く、scan がヒットする……といった症状 → 根本原因 → 処置のクイックリファレンスです。

## 設計上の説明

- **ルーティング型 skill であり、新たな CLI ではない**：新しいランタイムを持ち込まず、「状態を読む → おすすめする → 既存のコマンド／フローを実行する」を agent がたどれる指示としてコード化しただけです。下層の能力はすべてリポジトリ既存のものです（三つの AI CLI、同期スクリプト、検証ゲート）。
- **提案より先に状態**：コーチは感覚でおすすめすることを禁じられています——スナップショットの全フィールドに検出コマンドがあります（`skills/references/state.md`）。進捗統計の口径は `apps/quiz-app/src/lib/progress.ts` と完全に一致します（墓碑フィルタ、ランダムサンドボックスは主進捗に入れない、間違えた問題の卒業しきい値、SRS の期限）。
- **方法論の内蔵**：おすすめアルゴリズムの順序はそのまま [`methodology.ja.md`](./methodology.ja.md) の「アウトライン → 教材 → 問題演習」の実装です。F2 フローは、まず MISSION（出題ポイント配置表を含む）と RESOURCES を書くことを強制してからコースと問題の生成を許します——問題の生成は裸の JSON を書くことではなく、配置表に沿って出題ポイントごとに直接生成し、三つのゲート（qa / scan / 四つの整合）がすべてグリーンで閉じることです。

## 拡張

新しいフローを追加するには：`skills/ask-coach/references/` のフロー playbook に節を一つ追加し（目的／前提／手順／完了の目安）、`SKILL.md` のメニューと意図ルーティング表に一行を加えます。変更したら `pnpm run sync:plugin` でプラグイン成果物を再生成します（手動インストールのユーザーは別途 `pnpm run skill:install` を再実行して再配布）。薄いコマンドを追加するには：`skills/` に新しいディレクトリを作って薄い SKILL.md を書きます（十数行。`../ask-coach/references/` を共有）。sync-plugin が自動的に成果物へ取り込みます。

## FAQ

**Q: インストールは必須ですか？**
A: しなくても使えますが、毎回自分で「次に何をするか」を考える必要があります。入れておけば一言で始められます。

**Q: 私のデータを書き換えたりしませんか？**
A: Step 1/2 は純粋な読み取り専用です。Step 3 はあなたが選んだフローを実行するときにのみファイルを書き／コマンドを走らせます。しかも playbook には赤線（禁止事項）が明記されています（同期成果物の手編集禁止、進捗ファイルの手編集禁止）。

**Q: AI CLI を乗り換えても使えますか？**
A: 使えます。skill は markdown の指示＋参考ドキュメントにすぎず、skills ディレクトリの規約をサポートするクライアントならどこにでもインストールできます（`--dest` で指定）。
