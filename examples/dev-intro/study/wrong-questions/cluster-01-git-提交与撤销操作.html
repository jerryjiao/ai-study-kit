Git 提交与撤销操作精讲

在做这两道题时，我们触及了 Git 日常工作中最核心的两个动作：如何把改动存入历史，以及如何安全地反悔。很多初学者容易混淆“本地提交”与“远程推送”的概念，或者在需要撤销时选错了工具，导致代码丢失或团队协作灾难。下面我们结合“三区模型”来彻底搞懂这些命令。

1. 基础复盘：提交的三区流转（针对 GIT-003）

在题目 [GIT-003] 中，你选择了 git push，这是非常典型的误区。我们需要回到 Git 的三区模型（工作区、暂存区、版本库）来理解：

  • 工作区：你肉眼看到的文件，正在修改的代码。
  • 暂存区：通过 git add 后，准备提交的文件列表。
  • 版本库：通过 git commit 后，生成了版本快照的地方。

git commit 的作用是将“暂存区”的内容快照永久保存到“版本库”，并附带说明（-m）。而 git push 是将“版本库”的内容同步到“远程仓库”。你选 A 的原因可能是认为“提交”就是上传，但实际上 Commit 是本地存档，Push 是云端同步。如果没有先 Commit，Push 是无数据可传的。

正确命令：git commit -m "说明"。

维度 git reset git revert
操作本质 回退指针：移动 HEAD 指针到旧版本，就像时光倒流。 新建提交：创建一个新的“反向提交”来抵消改动。
历史记录 改变历史：被撤销的提交在当前分支历史中消失（选项 A 正确）。 保留历史：原提交和撤销提交都存在，历史完整（选项 B 正确）。

适用场景 本地私有分支清理，或尚未 push 的提交。 已推送到团队共享分支的紧急修复（选项 D 正确）。

关于选项 C，虽然最终代码效果可能一样（文件都变回去了），但它们对版本库的影响截然不同，绝对不能在团队协作分支上互换使用，否则会重写队友的历史。

3. 决策流程图：我该用哪个命令？

当你想要撤销某个提交时，请遵循以下决策树：

开始：想要撤销某个提交？
│
├─ 1. 这个提交是否已经 push 到远程仓库？
│   │
│   ├─ [YES] 已推送 (队友可能已基于此工作)
│   │   └─> 必须使用 git revert [commit-hash]
│   │       (原理：追加一个反向提交，不破坏历史)
│   │
│   └─ [NO] 未推送 (仅在你本地可见)
│       │
│       ├─ 2. 你想彻底丢弃这次提交的改动吗？
│       │   │
│       │   ├─ [YES] 丢弃代码
│       │   │   └─> 使用 git reset --hard [target-hash]
│       │       (注意：工作区改动也会丢失！)
│       │   │
│       │   └─ [NO] 保留代码，仅撤销提交
│       │       └─> 使用 git reset --soft [target-hash]
│       │           (效果：改动回到暂存区，你可以重新修改后 commit)
│       │
│       └─ 3. 仅仅修改上一次提交的说明/漏加文件？
│           └─> 使用 git commit --amend

4. 易错警示

⚠️ 警示 1：混淆 Commit 与 Push

再次强调，git push 是“上传”，不是“存档”。如果题目问的是“提交暂存区到版本库”，永远是 commit。只有当你想把版本库同步给 GitHub/GitLab 时，才用 push。

⚠️ 警示 2：严禁 Reset 公共分支

如果多人协作的分支（如 main 或 develop）已经被你 push 过了，千万不要用 git reset 去回退版本。这会导致你的本地历史和远程历史分叉，队友下次 pull 时会遭遇巨大的冲突灾难。此时必须老老实实用 git revert。

5. 变体训练

📝 变体题 1

题干：小王不小心将包含密码错误的配置文件 config.env 提交并推送到了团队的 master 分支。为了消除这个错误，同时不破坏队友的本地历史，他应该执行下列哪条命令？

A. git reset HEAD~1 --hard
B. git commit --amend
C. git revert HEAD
D. git branch -D HEAD

解析：注意关键词“已推送”和“不破坏队友历史”。Reset 会改变历史，Amend 只能改未推送的上一个提交。正确答案是 C。

📝 变体题 2

题干：你刚刚执行了 git commit -m "fix bug"，但突然发现还有一个文件 patch.js 忘记加进去了。你不想新建一个新的提交，而是想把 patch.js 合并到刚才的提交里，应该怎么操作？

A. git add patch.js; git commit -m "fix bug"
B. git add patch.js; git commit --amend --no-edit
C. git reset --hard HEAD; git add patch.js; git commit
D. git push -f

解析：这是修正“最后一次提交”的经典场景。先 add 把文件放入暂存区，然后用 --amend 修改上一次提交。答案 B。注意 --no-edit 表示不修改提交信息，如果想改信息可以去掉它。
