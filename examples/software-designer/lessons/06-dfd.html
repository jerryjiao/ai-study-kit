ai-study-kit 学习包　·　← mission　·　下一课：D7 · UML 与设计模式

结构化方法分两步：SA（Structured Analysis，结构化分析）用数据流图＋数据字典把「数据在系统里怎么流」画清楚；SD（Structured Design，结构化设计）再把加工映射成模块，完成模块设计。下午案例第一道大题考的正是这条链路——本课按典型题问法带你过一遍。

一、数据流图（DFD）：案例必考画图题

数据流图（Data Flow Diagram, DFD）从「数据流动」的视角刻画系统，只有四类元素，多画任何东西都算错：

元素含义记法
外部实体系统之外的数据源/数据宿（人或外部系统）矩形框，如「旅客」
加工对数据的变换，动宾命名并编号圆角框/圆圈，编号 1、1.2 逐层展开
数据存储静止存放的数据（文件、表）开口矩形/双横线，编号 D1、D2
数据流数据的流向与内容带名字的箭头

订票系统 0 层数据流图片段（典型题风格）：

[旅客] ──订票请求──▶ (1 校验余票) ──余票查询──▶ ⟨D1 车次余票⟩
  ▲                     │ ◀──余票信息── ⟨D1⟩
  │                     ├──出票请求──▶ (2 开票收款) ──客票──▶ [旅客]
  └──无票答复───────────┘                    │
                                             └──售票记录──▶ ⟨D2 售票流水⟩

分层：顶层图（关联图）只画一个加工代表整个系统，确定边界；往下逐层展开为 0 层、1 层图，加工编号 1 → 1.1 / 1.2 / 1.3。

父图与子图平衡规则（下午补图题的钥匙）：子图的输入、输出数据流必须与父图中对应加工的输入、输出数据流一致（条数、方向、内容）。题目挖掉一条数据流时，先在父图数进出，再回子图对账，缺哪条补哪条。

典型题问法与解题四步

  1. 圈词：说明里的名词 → 外部实体/数据存储候选；动词 → 加工候选；「向…提交/返回…」→ 数据流候选。
  2. 查连线：每条数据流必须至少有一端接加工——实体→实体、实体↔存储直连都是错图。
  3. 查加工：有入无出是「黑洞」，有出无入是「奇迹」，都要回说明找缺失的数据流。
  4. 查平衡：用父图与子图平衡规则核对展开后的输入输出。

二、数据字典（DD）：给 DFD 的每条流做注解

数据字典（Data Dictionary, DD）对数据流图里的数据流、数据存储和加工做精确定义，四类条目：

条目类型定义什么示例
数据项（数据元素）不可再分的最小数据单位、取值类型与范围车次号 = 1 个字符＋4 位数字
数据流流动数据包的组成订票请求 = 旅客姓名＋车次号＋乘车日期＋(座位偏好)
数据存储存储数据的组成与组织D2 售票流水 = {售票记录}
基本加工最底层加工的加工逻辑（怎么算）用三工具描述，见下

常用定义符号：

=        定义为            +        与（顺序连接）
[.. | ..] 或（多选一）      {..}     重复       m{..}n  重复 m~n 次
(..)     可选              ".."     取值范围   "1".."9"
例：订票请求 = 旅客姓名 + 车次号 + {行程段} + (座位偏好)

加工逻辑三工具（描述底层加工「做什么、怎么做」）：

  • 结构化语言：顺序/选择/重复三种控制结构＋自然语言，如「IF 余票>0 THEN 开票 ELSE 登记 D3」。
  • 判定表：多条件组合出多动作，最不易遗漏分支。
  • 判定树：判定表的树形画法，直观易读。

三、模块设计：从 DFD 到结构图

SD 阶段把数据流图映射成结构图（程序模块结构），两条映射路径：

变换流：  逻辑输入 ──▶ 变换中心 ──▶ 逻辑输出     （变换分析：按输入/变换/输出三分模块）
事务流：  事务 ──▶ 事务中心 ─┬─▶ 动作 1          （事务分析：按动作分支分模块）
                             ├─▶ 动作 2
                             └─▶ 动作 3

评价模块设计好坏的两把尺：耦合（模块间联系，越低越好）与内聚（模块内联系，越高越好）——好设计就是「高内聚、低耦合」。

耦合七级（从好到差）含义
非直接耦合两模块无直接联系
数据耦合只传简单数据参数（目标状态）
标记耦合传数据结构（一部分用不到）
控制耦合传控制变量（开关/标志），对方决定做什么
外部耦合访问同一全局简单变量（如 I/O 约定）
公共耦合共享公共数据区（全局结构）
内容耦合直接访问对方内部数据/代码（最差）
内聚七级（从好到差）含义
功能内聚只做一件事且做好（目标状态）
顺序内聚前一个输出是后一个输入
通信内聚用同一组输入/输出数据
过程内聚按控制流顺序执行，数据关系弱
时间内聚同一时间执行（如初始化模块）
逻辑内聚逻辑上相似功能凑一起，靠参数选择
偶然内聚无关系的语句拼成模块（最差）

模块设计启发式规则（判断题高频）：扇入尽量大（被更多上层复用）、扇出尽量小（一般 ≤7）；模块规模适中；模块作用域应在其控制域之内；尽量单入口单出口；消除重复功能。改造结构图的每一步都是朝着高内聚、低耦合走。
