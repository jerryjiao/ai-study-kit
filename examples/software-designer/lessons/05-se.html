D5 · 软件工程基础

ai-study-kit 学习包　·　← mission　·　下一课：D6 · 结构化分析与设计

软工是上午大分值区也是下午背景知识：开发模型对比、需求分析分类、软件测试方法、项目管理计算、软件维护类型。开发者做这些题有体感，重点是记住教材口径的「标准答案」。

一、开发模型

开发模型解决「过程怎么组织」，选择题考特征匹配：

模型核心特征适用
瀑布阶段线性顺序、文档驱动需求明确稳定
增量按构件分批交付可运行产品可拆分交付
原型快速造原型澄清需求需求模糊
螺旋每轮迭代都做风险分析大型高风险
统一过程用例驱动、以架构为中心、迭代增量—

易错：「每轮迭代都含风险分析」是螺旋模型的独有标签；喷泉模型面向对象、无间隙迭代。

二、需求分析

需求分析产出《需求规格说明书》（SRS），是后续设计与验收的基准。

  • 需求分类：功能需求 vs 非功能需求（性能、可靠性、安全性、易用性、可维护性……）。
  • 需求工程过程：需求获取 → 分析 → 定义（编写 SRS）→ 确认（评审）→ 管理（变更控制）。
  • 结构化分析方法（SA）的核心工具：分层 DFD + 数据字典——详见下一课。
  • 需求评审验证的是「正确、完整、一致、可行」，不是设计模块或估算成本。

三、软件测试

软件测试分白盒黑盒两个视角，考覆盖强度与方法命名：

  • 白盒（结构）：语句覆盖 < 判定覆盖 < 条件覆盖 < 判定-条件覆盖 < 条件组合覆盖 < 路径覆盖（强度递增）。
  • 黑盒（功能）：等价类划分、边界值分析、错误推测、因果图。
  • 阶段：单元测试（桩/驱动模块）→ 集成测试（自顶向下用桩、自底向上用驱动）→ 确认测试（验收）→ 系统测试。
  • 回归测试：修改后再跑旧用例，防改错扩散；α 测试在开发方场所、β 测试在用户场所。

四、项目管理

项目管理考进度网络图计算：

关键路径 = 最长路径，总工期 = 关键路径长度
活动总时差 = 最迟开始 − 最早开始（关键活动时差为 0）
例：A(3)→B(4)→D(2)→E(4)：A-B-D-E 工期 13
    A(3)→C(2)→E(4)：工期 9 → C 所在路径时差 = 13−9 = 4
关键活动延误一天，总工期延误一天；非关键活动在其时差内延误不影响工期
  • 风险暴露 RE = 风险概率 × 风险损失。
  • Gantt 图展示进度安排，不体现任务依赖；PERT 图（网络图）体现依赖。

五、软件维护

软件维护四类型，比例口诀「纠适完预」：

类型对象占比（教材口径）
纠正性改错~20%
适应性适配环境变化~25%
完善性扩充功能/改进性能~50%（最大头）
预防性为将来可维护性~5%

记忆锚点：维护费占软件生命周期总成本的大头，其中完善性维护占比最大——两句话覆盖半数维护判断题。
