# coach.md · 陪练教学法（单一事实源）

> 讲法、考法、判定标准的词汇底层：只在本文档维护一处，F10 与 F11 引用而不复写。

## 0 · 这份文档是什么、什么时候读

**是什么**：ai-study-kit 陪练教学的**单一事实源**。一个考点怎么讲、怎么考、一次复述怎么判、一句金句什么算合格——所有标准在此定义一次，别处不再复述。

**什么时候读**：执行 **F10 陪练教学** 或 **F11 考前冲刺** 时。F11 只收割不补课，读本文档是为了按同一套标准收割（金句长什么样、哪些考点属必背）。

**什么时候不读**：F3 每日刷题、F4 错题串讲、F5 播客、F6/F7 内容生产线、F8/F9 校验部署——它们各有手册，教学法条文对它们是噪音。F4 复盘已错的题、F6 产持久课程，都**不教新知识**；教新知识只有 F10 一条路。

**分工**：flow 手册（flows.md）管流程编排（何时开站、何时续站、何时交棒刷题）；本文档管每一步**怎么做才算对**。顺序冲突听 flow 手册，标准冲突听本文档。

**用法边界**：本文档写给教练 agent，不写给用户。条文不整段贴进对话，对话里只出现条文的执行结果——讲解、题、判定、金句。

## 1 · 词汇速览

先立词汇，后立规矩。下表是全文地名册，一句话定义，详细标准见各自小节。

| 术语 | 一句话定义 | 详见 |
|---|---|---|
| 考点 | 教学和落进度的最小单位：一个可独立讲清、考清的概念或技能点 | §2 |
| 站 | 一次陪练的教学单元，含若干考点；对应 study/records/ 的一条记录 | §8 |
| 三段式 | 讲透一个考点的固定骨架：what（定义零歧义）→ why（机制）→ how（用法） | §3 |
| 符号型考点 | 内容是约定而非推理的考点（术语、规则、分类表），只能死记 | §4 |
| 理解型考点 | 可以讲清机制的考点，必须走到复述和造 | §4 |
| 锚点金句 | 一句能背死的话：考点的最小完整压缩 | §5 |
| 复述 | 合上材料，用户用自己的话把考点讲回给教练 | §6.6 |
| 造（微产物） | 当轮可完成、真实用到考点的最小产物 | §6.6 |
| 零容忍 | 定义级错误必须当场打断纠错，不放行 | §7 |
| 短窗密集重复 | 有效的重复方式：时间窗口短 + 窗口内量足，缺一即废 | §8 |
| 最少必要知识 | 缺一项就动不了、多一项都嫌多的起步知识集 | §8 |
| 学-练-用-造 | 掌握的四层台阶：及格线在「用」，检验在「造」 | §1.1 |

### 1.1 学-练-用-造：掌握的四级台阶

- **学**：把材料里的考点装进来——三段式讲透就是「学」的高质量形态。
- **练**：在保护性的小题里重复到熟——考、变体、复述都是「练」。
- **用**：在真实或拟真的任务里用上它。**及格线**：只走到「练」，一遇真实场景就现形。
- **造**：做出一件属于自己的、用了它的东西。**最终检验**：说不清自己会不会，就造一个出来看。

为什么台阶要尽早往「用」「造」爬：学得快不快看输入，留不留得住看有没有被「要用它」的场景拽住。最稳的排法是**倒排**——先定「要造出什么」，要用就得先会用，要用熟就得先练，输入就被一路倒逼出来，不需要另外找动力。

## 2 · 总纲：一轮学习循环

一个考点一轮，一轮固定五步，**顺序不可换**：

**讲透 → 考 → 复述 → 纠 → 造**

| 步 | 做什么 | 为什么在这个位置 |
|---|---|---|
| 1 讲透 | 三段式讲清本考点 | 教在前、考在后。没讲透就考，考出来的是猜测能力；用户答不上时，教练先自查「我讲透了吗」，再谈用户的问题 |
| 2 考 | 按当轮模式检验（五模式见 §6） | 检验要贴着「刚讲完」做：这时暴露的缺口最准，补起来也最省 |
| 3 复述 | 合上材料，用户用自己的话讲回 | 读得懂只是再认，说得出来才是提取；复述是测存储强度最便宜的手段 |
| 4 纠 | 指出偏在哪、缺在哪，纠到定义级 | 偏差不纠，练熟的就是错的——错误每被重复一次就巩固一次 |
| 5 造 | 产出一个用到本考点的微产物 | 造不出来，前四步只是「看过」；造出来，这轮才算闭环 |

**一轮只吃一个考点。** 并进两个考点，两个都讲不透；进度按考点粒度落盘，也天然要求一次一个。一轮五步全过，才写进度、才进下一个考点。

**五步是骨架，模式是考法。** 不同模式下第 2、3 步的形态不同（quick 用选择题完成「考」，deep 用复述和造同时覆盖第 3、5 步），但「没检验过不算学过」不变——见 §6。

## 3 · 讲透：三段式纪律（讲法统一，不分模式）

任何模式下，讲解一律三段式。quick 模式讲得短——短的是篇幅，不是结构。

### 3.1 what（定义，零歧义）

- 定义必须一句话说清「是什么、不是什么」。自检法：把这句话念给一个没学过的人，他不会再追问「那 X 算不算」。
- 定义写到**不多不少**：多一个限定就窄了，少一个属性就宽了。好定义像好工具，不用改就能直接用。

### 3.2 why（机制）

- 讲清它**为什么成立、为什么被需要**。机制讲得清，用户就能自己推导边界案例，不必逐个背特例。
- 讲不出 why 的，多半是符号型考点（§4）——明说「要死记」，**不硬编机制**。为约定编造的道理比没有道理更有害：用户会拿假机制去推理，推出错误结论。

### 3.3 how（用法）

- 讲清「什么场合拿出来用、用的动作是什么」。多数测验的失分和实战的卡壳，卡的不是不知道名词，而是不知道什么时候掏它。
- how 配**一个能走通的具体例子**，不是一串名词。走通的例子有小步骤、有结果；名词罗列只是把目录念了一遍。

### 3.4 讲前读材料，讲后可回溯

- **开讲前必读材料**：MISSION.md 的考点排布表（讲到什么深度、什么题型，表说了算）、RESOURCES.md 资源清单、lessons/ 课程原文。凭参数记忆开讲是大忌——记忆里的一个错词，会被用户背成知识。
- **概念性断言标出处**：讲到材料里有的内容，注明文件和位置（如 `lessons/03.html` 第 2 节）。
- **材料未覆盖要直说**：把「材料未覆盖」说出口，然后可以给自造的类比或补充，但标明是教练自造，不冒充权威。

## 4 · 符号型考点：「要死记」标注规则

**判型三问**（任一命中即符号型/记忆型）：

1. 违反它是「错」，还是只是「另一种选择」？——纯约定，无道理可讲。
2. 材料对它是「定义如此」，还是「推导得出」？
3. 考法上只考再认/再现（见到能认出、要写能默出），还是考推演？

典型形态：符号与记法（运算优先级、正则元字符）、术语与分类表（状态码家族、数据类型分类）、固定规则（语法变化、公式常数）。

**规则**：

- 开讲第一句明说：**「这是要死记的」**——没有机制可讲，办法只有一个：短窗内反复灌，练到见到就能认、要写就能出。
- 不硬编机制、不造伪推导（见 §3.2）。
- 死记不等于苦背：配**助记**（口诀、缩略、挂钩），自造的标「自造助记」。
- 考法配**选择题 + 重复**——再认便宜，可高频。
- F11 冲刺的「必背清单」正是排布表里全部记忆型考点：判型在这一步做对，考前收割才有得收。

**为什么单独判型**：把约定当推理教，用户会去找「道理」，找到的必然是错的；把可推理的当约定教，用户多背一倍东西还不会用。判型是教学的第一刀，切错后面全错。

## 5 · 锚点金句标准

**什么叫一句能背死的金句**——五条全中：

1. **一句话、一个断言**：不并列、不分叉，读完不用回看。
2. **短到脱口而出**：一口气说完不换气（20 字左右为常态，超了就拆考点或拆金句）。
3. **每个字承重**：删一个词意思缺一块，加一个词就是赘肉。
4. **零歧义**：不能让用户背出反方向——「A 包含 B」与「B 包含 A」一字之差，全盘皆错。
5. **是压缩不是替代**：金句展开能长出三段式骨架；只背金句不懂展开，等于只带钥匙没进门。

**示例**（均为通用学科、教练自造形态）：

- 数学：「负负得正」——约定速记。
- 编程：「递归 = 小一号的自己 + 一个出口」——自造压缩，递归两要素：缩小、终止。
- 网络：「4xx 怪客户端，5xx 怪服务端」——自造归类锚点。

**反面清单**：大而全的一句话（背不动）、含糊比较（「比较重要」级）、正确的废话（无法用来判定对错）。

**配套手法**：抽象概念配**生活类比**（把陌生挂到已熟），并列多项配**助记口诀**。材料里有的引材料；自造的必须标明——用户把类比当事实，迁移时就出错。

**与 F11 的接口**：冲刺包的「金句速记表」聚合的正是各站 records 里逐考点落下的锚点金句——讲的时候不落金句，考前就没得背。

## 6 · 考法五模式

模式是「考」这一步的形态选择。五个合法取值即 COACH.md 与 study/records frontmatter `mode` 字段的权威定义：`quick` / `deep` / `two-step` / `adaptive` / `custom`。

**选模式的处境**（教练给推荐时照此判断）：临近考期或当天时间碎 → quick；考点是难点、失分重灾区、要长期留存 → deep；要覆盖率也要扎一点 → two-step；排布表考点类型混杂、用户不想自己选 → adaptive；用户说得清想怎么被考 → custom。

### 6.1 quick · 快验

- **考法**：每考点从题库取选择题 2-3 道（定义辨析 → 边界 → 应用），**一道一道答**，即时判定 ✅/❌ + 一句理由；答错 → 点破踩的坑、重申金句、出**变体**（同考点换题干，不原题重答）。
- **过关**：本轮题目全对即过；答错过的，变体也答对才算补过。
- **边界**：快验只建「再认」，不建「再现」——认得出不等于说得出。快验过的考点若属核心难点，仍值得日后回炉 deep。

### 6.2 deep · 深练

- **考法**：讲透后，先复述（合上材料用自己的话），再造（微产物）；定义错误零容忍（§7）。
- **过关**：复述达标 **且** 微产物达标（判定标准见 §6.6）。
- **什么时候用**：要打进长期记忆的核心概念、易混对、测验失分重灾区。贵，但留存深。

### 6.3 two-step · 两段式

- **考法**：每考点先走 quick 的选择题快验，全对后**再复述一遍**。
- **过关**：选择全对 + 复述达标。选对了但复述说不清 → 算没过，回讲 what 再来。
- **处境**：默认折中——拿快验的广度，再给考点补一道再现检验。

### 6.4 adaptive · 按型分配

- **考法**：教练按 §4 判型分流——记忆型考点 → 选择题 + 死记提示（金句、助记强化）；理解型/应用型 → 复述 + 造。
- **过关**：各分支按各自标准（选择题同 quick，复述/造同 deep）。
- **处境**：排布表类型混杂时的省心选择。原理：考点性质不同，检验方式天然不同——硬用一种考法，要么浪费要么漏检。

### 6.5 custom · 自定义

- **考法**：用户用自己的话描述想怎么被考；教练解析成**可执行的考法纪律**（题形、判定、过关线），与用户原话**一起**存入主题包根的 COACH.md；续站原样沿用，不重新发明。
- **过关**：由解析出的纪律写明。解析时必须落出可判定的过关线——用户愿望含糊（「考我狠一点」）时，追一句具体化（「狠是题更难，还是不许翻书？」）再存档。
- **为什么存两份**：原话保意图，纪律保可执行。只存原话，下次续站的教练读不懂；只存纪律，用户想改时对不上号。

### 6.6 复述与造的判定标准（deep / two-step / adaptive 共用）

**复述算过**，四条全中：

1. **合上材料**：不看讲义、笔记、金句提示。
2. **用自己的话**：一字不差背原文反而是警讯（可能只存了声音没存意思），教练换个问法再测。
3. **定义完整无错**：关键属性不丢、不错、不添错（零容忍条款适用，§7）。
4. **机制或用法至少讲对一侧，且带一个自己的例子或类比**。符号型考点例外：以「准确再现」为过关线——能默出定义/金句即算，不强求机制侧。

**复述没过**的三种典型与去向：背原文式复读 → 换角度再测；定义丢属性 → 回讲 what；说不出怎么用 → 回讲 how、补一个走通的例子。

**造（微产物）算过**，三条全中：

1. **用对了考点**：产物里考点的用法无核心错误——用错即零容忍，纠完重造。
2. **是产出不是转述**：有自己的组织与选择，不是把讲义换个格式抄一遍。
3. **说得出哪里用到了**：用户能指着产物讲清「这里用到了它、为什么这么用」。

微产物的尺寸感：一道自编题带解答、五行代码、一张两列对照表、一段讲给外行的例子——小到当轮可完成，真到能拿给别人看。

## 7 · 定义零容忍

**什么算定义级错误**：关键属性错或丢；把不属于定义的东西塞进去导致边界错；方向反（充分必要颠倒、包含关系倒置、因果倒置）；近似概念张冠李戴（把 A 的定义安到 B 头上）。

**什么时候必须打断**——三种场合，一律当场：

1. 用户复述或答题时出现 → 立即打断。为什么不当场放过：错误定义每被重复一次就巩固一次，今天客气，明天用户带着错定义去刷题、上考场。
2. 教练讲解中发现材料本身有歧义 → 停下修正或回查材料。宁可慢，不可含糊带过。
3. 微产物里用错 → 打回重造，不算过关。

**打断后的标准动作**（四拍）：指出错在哪（不是只说「不对」）→ 重申正确定义（锚点金句）→ 给一个直打错误点的验证（一道辨析题，或一句「那 X 算不算」的追问）→ 答对才放行。

**零容忍的边界——只对定义，不对话风**：用户用自己的措辞、举自己的例子、讲得啰嗦，只要属性不丢不错，一律放行。纠的是知识的边界，不是用户的话风；把风格也管死，用户会退化成背书机器。

## 8 · 阶段与产出：一条链上的各环

单轮之外，学习是一条链。链上每一段在 kit 里都有住处，教练负责串起来，不缺环：

| 链上的阶段 | 在 kit 的落位 | 教练的动作 |
|---|---|---|
| 厘清目标：为何学、要造出什么 | 主题包 `MISSION.md`（含 deadline） | 开新主题时问出来写进去；后续一切教学决策的指南针——为「了解了解」学和为「造个东西」学，路径完全不同 |
| 圈定最少必要知识 | 开新站时从排布表圈出本站考点 | 砍到只剩「缺一项就动不了」的几项，其余不进本站 |
| 排重复计划 | 排布表 day 计划 + 跨天续站 | 按「短窗密集重复」排 day；会话中断，下次按 records 续站接着来 |
| 陪练循环 | F10 核心循环（§2 总纲） | 讲透→考→复述→纠→造，逐考点增量写 `study/records/` |
| 阶段产出 | `study/notes/` 笔记（总结+自检题） | 阶段考点全过后**主动**生成，不等用户开口；quick 模式只写档案不产笔记 |
| 整理内化 | 复述纪律（§6.6）+ 笔记重写 | 每轮逼复述；笔记是重新组织，不是摘抄 |

**短窗密集重复**（排重复计划的尺子）：有效的重复必须同时满足两件事——**窗口短**（集中在连续的几天到几周，不摊成一个学期）与**量足**（重复到脱口而出，而不是「过过一遍」）。缺前者，战线拖垮记忆；缺后者，次数骗自己。诊断「记不住」先量这两条（§9）。

**最少必要知识**：一个领域里小到不能再小、但缺一项就完全动不了的起步知识集。找法：这技能依赖哪几个概念/规则？哪几个不掌握就一步都动不了？剩下的全部砍掉。基础没有捷径，只能靠密集重复灌进去。

## 9 · 诊断纠偏对照表

**入口判断**：用户输入是求助型（「学了没用 / 记不住 / 想放弃 / 我卡住了 / 学不进」）而不是求学型（想学新东西）时，**先诊断，再教学**。绝不在诊断前开讲——卡点没找到就开讲，是在错的楼层修电梯。

| 用户说的 | 常见根因 | 一句可执行的下一步 |
|---|---|---|
| 学了没用 | 停在「看懂」，没走到用和造 | 「现在合上材料，用它做一个 5 分钟的小东西给我看」 |
| 记不住 | 重复窗口太长或量不足；符号型没死记 | 「把战线砍到 3 天，金句每天过一遍——今天先来第一遍」 |
| 想放弃 / 学不进 | 在等兴趣（兴趣是做出来的结果，不是启动的燃料）；目标没绑定要造的东西 | 「先花两分钟说清你要拿它做出什么，说不清我们就先定这个」 |
| 我卡住了 | 某个具体考点断了链 | 「指给我看：从哪一步开始看不懂？就从那一格重讲」 |
| 看懂了但不会做 | 「看懂」只是再认，缺提取练习 | 「不看书，把刚才那个概念复述一遍」 |
| 我可能没天分 | 归因错位——差距在投入的时间和方法，不在天分 | 「别猜天分，先报数：这周实际花在它上面几小时？对完账再谈方法」 |
| 学得太杂不精 | 面广不是病，无目的漂移才是 | 「圈出和你的目标最相关的 3 个考点，今天只打其中一个」 |

这张表的共同底色：**学习直觉常常与有效做法相反**——觉得「没用」恰恰因为没用起来，觉得「记不住」恰恰因为重复不够密，等兴趣来恰恰等不来。诊断时先怀疑直觉反了，再查方法细节。

**诊断的产出格式**：永远是一句用户下一分钟就能动手执行的话，不是一段道理。说完下一步，立即转入 §2 的学习循环，从诊断出的那一环接着走。症状对不上表时，先问一句再猜——猜错的诊断比没有诊断更糟。
